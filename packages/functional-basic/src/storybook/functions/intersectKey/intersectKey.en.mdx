# `intersectKey`

Analyzes two objects or arrays and returns a new plain object with the keys shared by `data` and the own properties of `comparison` (checked with `hasKey`). Values come from `data`. Objects contribute their own enumerable string keys; arrays contribute their numeric indexes. Inherited properties of `comparison`, such as array methods, do not match.

The keys `__proto__`, `constructor`, and `prototype` are always excluded, even when both inputs define them as own properties. This prevents copying `__proto__` from changing the result's prototype. Other own keys such as `toString` and `valueOf` remain supported. Values, including `undefined`, are copied shallowly.

This function is highly useful for filtering payload data against an allowed schema footprint or synchronizing partial models.

**Parameters:**
- `data?: T | null` — The source record or mutable/readonly array that supplies the values.
- `comparison?: C | null` — The reference record or mutable/readonly array whose own keys are checked.

**Returns:**
A new plain object; it is never an array. Missing or nullish inputs produce `{}`. Generic constraints admit records and readonly arrays, while primitive inputs remain outside the TypeScript contract.

- Array `data`: `Partial<Record<number, T[number]>>`, without array methods or `length`.
- Record `data` with array `comparison`: `Partial<Pick<T, Extract<keyof T, keyof C>>>`, because a property may be inherited rather than owned by the array.
- Two records: `Pick<T, Extract<keyof T, keyof C>>`.

```typescript
import { intersectKey } from '@dxtmisha/functional-basic'

const inputData = { id: 1, name: 'John', age: 30, _internalToken: 'xyz' }
const allowedSchema = { id: null, name: null, role: null }

// Returns only the keys from inputData that are present in allowedSchema
const result = intersectKey(inputData, allowedSchema)
console.log(result) // { id: 1, name: 'John' }
```
