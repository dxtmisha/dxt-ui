# `intersectKey`

Phân tích hai đối tượng hoặc mảng và trả về một đối tượng thường mới với các khóa chung giữa `data` và thuộc tính riêng của `comparison` (kiểm tra bằng `hasKey`). Giá trị được lấy từ `data`. Đối tượng được duyệt theo khóa chuỗi riêng có thể liệt kê, còn mảng theo chỉ số. Thuộc tính kế thừa của `comparison`, chẳng hạn phương thức mảng, không được khớp.

Các khóa `__proto__`, `constructor` và `prototype` luôn bị loại, kể cả khi cả hai đầu vào đều có các khóa này dưới dạng thuộc tính riêng. Điều này ngăn việc sao chép `__proto__` làm đổi prototype của kết quả. Các khóa riêng khác như `toString` và `valueOf` vẫn được hỗ trợ. Giá trị được sao chép nông, bao gồm cả `undefined`.

Hàm này rất hiệu quả trong việc hỗ trợ lọc bỏ các trường dư thừa từ payload khi tra soát chéo với một cấu trúc object mẫu an toàn.

**Tham số:**
- `data?: T | null` — Record hoặc mảng có thể thay đổi/readonly cung cấp giá trị nguồn.
- `comparison?: C | null` — Record hoặc mảng có thể thay đổi/readonly có các khóa riêng cần kiểm tra.

**Trả về:**
Một đối tượng thường mới, không bao giờ là mảng. Đầu vào bị thiếu hoặc nullish trả về `{}`. Ràng buộc generic chấp nhận record và mảng readonly; giá trị nguyên thủy vẫn nằm ngoài hợp đồng TypeScript.

- `data` là mảng: `Partial<Record<number, T[number]>>`, không có phương thức mảng hay `length`.
- `data` là record và `comparison` là mảng: `Partial<Pick<T, Extract<keyof T, keyof C>>>`, vì thuộc tính có thể được kế thừa thay vì là thuộc tính riêng của mảng.
- Cả hai là record: `Pick<T, Extract<keyof T, keyof C>>`.

```typescript
import { intersectKey } from '@dxtmisha/functional-basic'

const inputData = { id: 1, name: 'John', age: 30, _internalToken: 'xyz' }
const allowedSchema = { id: null, name: null, role: null }

// Chỉ giữ lại những trường từ inputData mà xuất hiện trong allowedSchema
const result = intersectKey(inputData, allowedSchema)
console.log(result) // { id: 1, name: 'John' }
```
