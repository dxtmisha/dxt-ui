# About the Library

The **`@dxtmisha/constructor`** package is the core engine and foundation of the design system, providing over 110 ready-to-use component constructors for Vue 3 and TypeScript.

The library follows the **Headless UI** architecture: all business logic, reactive state management, event handling, accessibility (WAI-ARIA), and keyboard navigation are encapsulated inside independent constructor classes, completely decoupled from visual presentation.

## Design System Architecture Overview

The `@dxtmisha/constructor` package serves as the core foundation for creating production-ready UI libraries (such as `@dxtmisha/d1`):

```text
┌─────────────────────────────────────────────────────────────────────────┐
│                 1. Logic Engine (@dxtmisha/constructor)                 │
│  • 110+ abstract classes (Button, Modal, Input, Table, Select...)       │
│  • WAI-ARIA accessibility, keyboard navigation & Focus Trap             │
│  • Reactive states (:focus, :active, :hover, loading, disabled)         │
│  • Form input management, data validation & input masking               │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                   2. Build Tooling (@dxtmisha/scripts)                  │
│  • dxt-ui generator: bridges constructor logic with design tokens       │
│  • Automated generation of props.ts, styleToken.scss & exports          │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│               3. Design System (Example from @dxtmisha/d1)              │
│  • Design token configuration in src/media/ (colors, typography, grid)  │
│  • D1*.vue components: wire constructor logic with BEM classes          │
│  • SCSS styling: visual tokens applied via @dxtmisha/styles mixins      │
└─────────────────────────────────────────────────────────────────────────┘
```

## Key Benefits of Using the Constructor

- **Multi-Design Scalability**: A single Constructor core simultaneously powers multiple distinct UI kits (such as `@dxtmisha/d1`, enterprise themes, mobile-first designs). Creating a new design system no longer requires rewriting the logic for 110+ components — only defining tokens and templates is needed.
- **Centralized Bug Fixes (Single Point of Fix)**: Resolving edge cases, mobile browser quirks (iOS/Android), keyboard navigation, or input mask issues in the Constructor core automatically fixes them across all connected design systems upon package update.
- **Safe Evolution Without Regressions (Zero Regression)**: Adding new features or props to Constructor expands the capabilities of all design kits without breaking their visual layout. Conversely, redesigning styles or tokens cannot break underlying logic (a11y, focus, overlays).
- **Guaranteed Accessibility (a11y)**: Every constructor fully adheres to the WAI-ARIA specification out of the box.
- **Reduced Maintenance Overhead (TCO)**: Business logic is verified once at the Constructor level. UI kit testing focuses purely on visual tokens and layout.
- **Code Cleanliness & Rapid Development**: Eliminates boilerplate code and complex JS event handlers — new components are built in minutes by wiring a pre-tested constructor class.

## Features & Capabilities of @dxtmisha/constructor

The constructor covers all core requirements of modern frontend development:

### 1. Forms and Data Input
- **Text Inputs and Masks**: `Input`, `InputPhone` (with international dialing codes and auto-formatting), `InputCode` (SMS/2FA), `InputImage`, and `ImageCrop`.
- **Selection Controls**: `Checkbox`, `Radio`, `Switch`, `SegmentControl`, `Chip`, `ChipGroup`.
- **Selects and Dropdowns**: `Select`, `SelectValue`, `SelectableArea`.
- **Form Utilities**: Automatic character counters (`FieldCounter`), validation messages (`FieldMessage`), responsive labels (`FieldLabel`).

### 2. Overlays, Dialogs and Floating Surfaces
- **Modal Interfaces**: `Modal`, `Dialog`, `Window`, `ActionSheet`.
- **Popovers and Menus**: `Tooltip`, `Menu`, `MenuButton`, `MenuCountry`, `MenuLanguage`.
- **Notifications**: `Snackbar`, `SnackbarItem` with queue management.
- **Built-in Overlay Mechanics**: Automated focus trapping (Focus Trap), background scroll locking, `Escape` key and Click Outside dismissal, and anchor positioning (`Anchor`).

### 3. Navigation and Lists
- **Navigation Layouts**: `NavigationRail`, `Tabs`, `TabsNavigation`, `Breadcrumbs`, `Pagination`.
- **Lists and Accordions**: `Accordion`, `List`, `ListMenu`, `ListGroup`, `ListItem`.

### 4. Data Display and Content
- **Tables**: `Table`, `TableFlex`, `TableHeaderItem`, `TableRecord` (sorting, row selection, responsive columns).
- **Indicators and Skeletons**: `Skeleton`, `Progress`, `ProgressBar`, `Badge`, `Avatar`, `Bullet`.
- **Formatters**: `FormattedNumber`, `FormattedUnit`.

### 5. Motion, Scrolling and Interactivity
- **Scroll Management**: `Headroom`, `ScrollSticky`, `HorizontalScroll`, `Scrollbar`.
- **Motion Animations**: `MotionAxis`, `MotionFlip`, `MotionTransform`, `MotionSticky`.
- **Interactive Effects**: `Ripple`, `DraggableWrapper`, `Dropzone`.

## Supporting Ecosystem Packages

To support the constructor workflow, the ecosystem provides specialized packages:

- **`@dxtmisha/styles`** — SCSS framework with token architecture, two-tier opacity, responsive mixins, and dynamic palettes (`paletteBackgroundColor`, `paletteColor`).
- **`@dxtmisha/functional`** — Vue 3 Composition API composables, SSR isolation (`ServerStorage`), internationalization (i18n), and centralized vector icon management (`Icons`).
- **`@dxtmisha/scripts`** — CLI tools for component scaffolding (`dxt-ui`), library bundling (`dxt-library`), and documentation generation.
