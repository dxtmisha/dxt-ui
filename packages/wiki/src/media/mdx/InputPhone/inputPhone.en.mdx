A phone number input component combining automatic country dial code selection, dynamic phone masking, output formatting, and built-in validation.

InputPhone integrates the Field wrapper, InputPhoneDialCode country selector, and Mask formatting engine into a single component. It automatically detects the country as the user types, pastes, or autofills a phone number, switches the input mask accordingly, supports selector locking (`countryReadonly`), restricts allowed countries (`countryList`), or locks input to a local national format when `countryBlock` is enabled.

**Key features:**

- Automatic country detection by entered, pasted, or browser-autofilled phone number prefix (supports full-selection replacement, autofill prefix deduplication, and normalizing leading `+` + national `within` prefix such as `+8` to `+7`)
- Built-in `InputPhoneDialCode` selector with searchable country list, flags, dial codes (supports `XK` Kosovo `+383` and the full ISO country dataset), and direct `countryList` filtering
- Country lock modes: `countryBlock` (hides selector and switches to local format) and `countryReadonly` (locks selector while keeping flag and dial code visible; auto-locks for single-country lists)
- Output formatting (`formatOutput`: `'mask'` | `'e164'` | `'digits'`) and dedicated multi-model synchronization (`v-model`, `v-model:value`, `v-model:country`, `v-model:e164`, `v-model:digits`)
- Dynamic phone mask formatting with `Mask` (`maskAttrs`, `countryDefault`, `autocomplete="tel"` by default) and formatted `disabled` / `readonly` display
- Built-in validation (`required`, `pattern`, `validationCode`, `validationMessage`, `forceShowMessage`, `textInvalidPhone`), country-specific or custom `phoneMatch` validation rules (matching national phone digits or receiving full `InputPhoneValidationContext`), and non-blocking warning states (`warning`, `warningMessage`, `warningId`)
- Events (`input`, `inputLite`, `change`, `changeLite`, `focus`, `blur`, `update:country`, `update:e164`, `update:digits`) enriched with `detail` phone metadata, and exposed programmatic API (`getValue`, `setValue`, `clear`, `checkValidity`, `getValidationMessage`, `getDetail`, `isChanged`)
- Full slot support (`leading`, `trailing`, `prefix`, `suffix`, `label`) and accessibility (`inputmode="tel"`, ARIA popup controls)

**Common use cases:**

- User registration, checkout, and profile contact forms
- International phone inputs with E.164 or digits-only backend payloads
- Region-locked or whitelist-restricted phone inputs (`countryBlock`, `countryReadonly`, `countryList`)
- Validated contact forms with country-specific mobile prefix rules (`phoneMatch`), custom error messages, or non-blocking warning states
