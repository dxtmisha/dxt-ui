The `Page` component is a top-level semantic container designed to wrap the primary content of a view or document. It extends `Block` with a default `<main>` root tag, `<h1>` header level (`tagHeader`), and `'page'` area context.

`Page` provides a standardized header hierarchy (`headline`, `label`, `caption`, `icon`, `description`) while automatically linking `aria-labelledby` and `aria-describedby` to rendered header and description elements. When only default body content is provided, it omits the header/description wrapper and skips helper instantiation.

**Key features:**

- **Primary Landmark Semantics:** Wraps unique page content using the `<main>` root tag by default (configurable via `tag`)
- **Top-Level Heading Hierarchy:** Renders `<h1>` for the header label by default (`tagHeader`), anchoring the document outline above `Section` (`h2`), `Block` (`h3`), and `Group` (`h4`)
- **Full Block Capabilities:** Inherits `headline`, `label`, `caption`, `description`, leading `icon`, and all 6 slots (`#default`, `#headline`, `#label`, `#description`, `#caption`, `#trailing`)
- **Automatic ARIA & Area Context:** Synchronizes `aria-labelledby` and `aria-describedby` with generated or explicit `labelId` and `descriptionId`, and propagates `'page'` as the default reactive `area` context

**Common use cases:**

- Top-level wrapper for unique screen or route content
- Main application dashboard, article, or documentation view
- Root landmark container combining page title, description, and trailing actions
