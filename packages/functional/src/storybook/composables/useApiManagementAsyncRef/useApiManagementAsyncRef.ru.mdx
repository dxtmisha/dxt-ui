# `useApiManagementAsyncRef`

`useApiManagementAsyncRef` — это асинхронная обертка над [`useApiManagementRef`](./useApiManagementRef.ru.mdx), которая выполняет немедленную инициализацию запроса.

В отличие от стандартного `useApiManagementRef`, который инициализируется "лениво" (при первом обращении к списку или данным), этот метод вызывает `initSsr()` сразу при создании. Это делает его идеальным выбором для использования в SSR-окружении.

## Ключевые особенности
- **Немедленная инициализация** — запускает процесс инициализации GET-запроса сразу при вызове хука.
- **Поддержка SSR** — гарантирует, что данные будут загружены на сервере до рендеринга страницы.
- **Полная функциональность Management** — сохраняет все возможности `useApiManagementRef`, включая форматировщики, поиск и мутации.

## Параметры
Параметры полностью идентичны [`useApiManagementRef`](./useApiManagementRef.ru.mdx):

- `propsGet: ApiManagementGet<Return, Type>` — настройки главного GET-запроса.
- `formattersOptions?: FormattersOptions` — правила форматирования.
- `searchOptions?: ApiManagementSearch<Item, Columns>` — настройки поиска.
- `postRequest / putRequest / deleteRequest` — настройки мутаций.
- `action?: () => Promise<void> | void` — Общий колбэк после получения любого ответа на мутацию, независимо от успешности.
- `apiInstance?: ApiInstance` — экземпляр API.

Колбэки `action`, `actionSuccess` и `actionError` настраиваются отдельно в `postRequest`, `putRequest` и `deleteRequest`.

Методы `sendPost`, `sendPut` и `sendDelete` ожидают сначала `action` конкретной мутации, затем общий `action`. Пока колбэки выполняются, loading мутации остаётся активным. После общего колбэка успешный ответ запускает фоновое обновление GET; завершения этого GET методы `send` не ожидают. Если общий колбэк выбрасывает ошибку или возвращает отклонённый Promise, `send` возвращает `undefined` и завершает свой вызов. Loading остаётся активным, пока выполняются другие параллельные вызовы.

## Возвращаемое значение
Возвращает объект управления API. Состав возвращаемого значения полностью идентичен [`useApiManagementRef`](./useApiManagementRef.ru.mdx):

- `isValid: ComputedRef<boolean>` — `true`, если данные прошли проверку `typeData`.
- `isResponseContractValid: ComputedRef<boolean>` — `true`, если данные ответа соответствуют определенному контракту.
- `responseValidationResult: ComputedRef<ApiDataValidation | undefined>` — подробный результат валидации контракта.
- `list: ComputedRef` — обработанный массив данных с поддержкой Skeleton, форматтеров и поиска.
- `data: ComputedRef<ApiData<Return> | undefined>` — «сырые» реактивные данные из `useApiRef`.
- `errorItem: ComputedRef<ApiErrorItem | undefined>` — текущий объект ошибки, если запрос не удался.
- `length: ComputedRef<number>` — текущее количество элементов в `list`.
- `starting / loading / reading` — флаги состояния запроса.
- `loadingSearch / loadingPost / loadingPut / loadingDelete` — состояния загрузки для поиска и мутаций.
- `isSearch / search` — статус поиска и реактивная строка поиска.
- `sendPost / sendPut / sendDelete` — методы для выполнения мутаций.
- `reset / abort` — методы управления.

## Пример

```typescript
import { useApiManagementAsyncRef } from '@dxtmisha/functional'

// Инициализация (и SSR-предзагрузка) запускается немедленно
const { list, loading } = useApiManagementAsyncRef(
  { 
    path: 'api/products',
    skeleton: () => Array(3).fill({ id: 0, title: 'Loading...' })
  }
)
```
