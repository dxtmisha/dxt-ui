# `getIndexForRender`

Generates a composite component `key` from its name, indexes, and id. Identifiers are appended with dots; CSS classes are ignored.

### Parameters:
- `name?: unknown` — Component name or tag (the key base).
- `props?: T` — Component properties (used to extract `index` and `id`; `class` does not affect the key).
- `index?: string` — An optional external index.

### Returns:
`string | undefined` — The generated composite key, or `undefined` if no key could be generated.

### Generation Examples:

```typescript
import { getIndexForRender } from '@dxtmisha/functional'

// 1. Name only
getIndexForRender('li') 
// => 'li'

// 2. Name + external index
getIndexForRender('div', {}, 'row-1') 
// => 'div.row-1'

// 3. Name + index from props + id (class is ignored)
getIndexForRender('button', { 
  index: 'primary', 
  class: 'btn-large', 
  id: 'submit-01' 
}) 
// => 'button.primary.submit-01'

// 4. Full set (external argument + everything from props)
getIndexForRender('span', { 
  index: 'p-idx', 
  class: 'text-red', 
  id: 'id-99' 
}, 'arg-idx') 
// => 'span.arg-idx.p-idx.id-99'

// 5. Empty case
getIndexForRender(undefined)
// => undefined
```

### Key Assembly Logic

The key is assembled in a chain:
1.  **`name`** (if `name` is a string, without a leading dot)
2.  `+ .index` (if the `index` argument is passed)
3.  `+ .props.index` (if present in properties and is a string)
4.  `+ .props.id` (if present in properties)

CSS classes and styles do not participate in key generation. Changing presentation must preserve node identity, focus, and component state. For sibling list items, supply distinct stable identifiers through `props.key`, `index`, or `props.id`.
