# `render`

A wrapper around Vue's `h` (hyperscript) function that automatically generates component keys from stable identifiers.

**Parameters:**
- `name: Parameters<typeof h>[0]` — The name, tag, or component definition to render.
- `props?: T` — The properties to pass to the component.
- `children?: RawChildren | RawSlots` — The children or slots of the component.
- `index?: string` — An optional index or identifier to use for key generation.

**Returns:**
`VNode` — The rendered virtual node.

```typescript
import { render } from '@dxtmisha/functional'

// Renders a div with an automatically generated key
const vnode = render('div', { class: 'container' }, 'Hello World')
// key => 'div'

// Renders a component with a specific index for key generation
const item = render('my-component', { data: itemData }, null, 'item-1')
// key => 'my-component.item-1'
```

### Key Generation

An explicit `props.key` is preserved. Otherwise, the key is generated from these identifiers in order; a string component name has no leading dot, and subsequent identifiers are appended with dots:

1.  **`name`** — if `name` is a string.
2.  **`.index`** — from the fourth argument of `render`.
3.  **`.props.index`** — if provided as a string.
4.  **`.props.id`** — if an ID is specified in `props`.

CSS classes do not affect the generated key, so changing them preserves the DOM node and component state. An intentional change to an explicit `props.key` can still replace the node. Supply unique stable keys or identifiers for sibling list items; the component name alone does not guarantee uniqueness.
