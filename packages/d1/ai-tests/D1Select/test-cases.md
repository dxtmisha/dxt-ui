# Тест-кейсы визуального и интерактивного тестирования — D1Select

- **Компонент**: `D1Select` (`@dxtmisha/constructor/Select`)
- **Демо-страница**: `http://localhost:3000/component-select`
- **Дата спецификации**: `2026-11-25T17:26:41Z`
- **Среда**: Headless Chrome (CDP `127.0.0.1:9222`), разрешения `1440×900`, `768×1024`, `375×812`, `320×568`

## 1. Обзор матрицы покрытия

| Категория | Код | Количество кейсов | Покрытие |
| --- | --- | --- | --- |
| Визуальная верстка и токены | `VIS` | 2 | Базовые режимы, внешние виды, размеры, состояния (`disabled`, `readonly`, `focus`, `loading`, `skeleton`) |
| Интерактивность и состояние | `INT` | 3 | Открытие/выбор опции, автозакрытие, `expose` (`setValue`, `clear`, `getValue`), жизненный цикл `v-if` |
| Граничные значения и слоты | `BND` | 2 | Числовой `0`, пустой список, Unicode/Emoji/Кириллица, переполнение в узком `DemoBox`, слоты `Field`/`Menu` |
| Адаптивность | `RSP` | 3 | Планшет `768×1024`, мобильный `375×812`, узкий мобильный `320×568` (контроль горизонтального скролла) |

## 2. Детальные тест-кейсы

### 2.1. Визуальные проверки (VIS)

#### TC-VIS-001: Первичный рендер базовых режимов, вариантов и размеров на десктопе (1440×900)
- **Приоритет**: P0
- **Категория**: `VIS`
- **Предусловия**: Открыт маршрут `/component-select` при разрешении `1440×900`.
- **Шаги**: Дождаться полной загрузки страницы, проверить наличие всех 8 секций `D1Group`, всех 33 экземпляров `.d1-select`, отсутствие горизонтального переполнения.
- **Ожидаемый результат**: Все режимы (`Standard`, `With Search`, `Filter Mode`, `editValue`, `Arrow Carousel`, `Selection Style`, `v-model`, `Appearances`, `Sizes`, `States`) отрендерены ровно без визуальных дефектов; `scrollWidth === 1440`.
- **Тип доказательства**: Скриншот + DOM-метрики.

#### TC-VIS-002: Отображение состояний Disabled, Readonly, Loading, Skeleton и Validation
- **Приоритет**: P1
- **Категория**: `VIS`
- **Предусловия**: Загружена страница `/component-select`.
- **Шаги**: Проверить наличие и видимость отключенных полей (`disabled`), поля `readonly`, скелетона и валидационного сообщения в `D1Form`.
- **Ожидаемый результат**: Отключенные поля (включая `Disabled Selected`) имеют ненулевую геометрию и корректный приглушенный вид; сообщение `Selection is required` отображается под обязательным полем.
- **Тип доказательства**: DOM-метрики + скриншот.

### 2.2. Интерактивные сценарии (INT)

#### TC-INT-001: Открытие выпадающего списка по клику на триггер combobox
- **Приоритет**: P0
- **Категория**: `INT`
- **Предусловия**: Страница открыта в разрешении `1440×900`.
- **Шаги**: Кликнуть по первому `.d1-select input[role="combobox"]`, дождаться завершения анимации открытия `.d1-window`.
- **Ожидаемый результат**: Выпадающее окно открывается и отображает 8 видимых опций (`JavaScript`..`PHP`).
- **Тип доказательства**: Скриншот раскрытого списка + DOM-проверка.

#### TC-INT-002: Выбор опции в списке и автоматическое закрытие меню
- **Приоритет**: P0
- **Категория**: `INT`
- **Предусловия**: Выпадающий список из `TC-INT-001` открыт.
- **Шаги**: Кликнуть по второй опции (`TypeScript`), дождаться закрытия окна.
- **Ожидаемый результат**: Опция `TypeScript` выбрана, всплывающее окно закрыто (`visibleOptionsAfterClick === 0`).
- **Тип доказательства**: DOM-проверка.

#### TC-INT-003: Программное управление через Expose и переключение жизненного цикла (v-if)
- **Приоритет**: P1
- **Категория**: `INT`
- **Предусловия**: Страница открыта в разрешении `1440×900`.
- **Шаги**: Нажать `setValue('option1')` → `Read Expose` → `clear()` → `Read Expose` → `Unmount (v-if)` → `Mount (v-if)`.
- **Ожидаемый результат**: `Expose State` сначала показывает `value="option1"`, после `clear()` — `value=undefined`; размонтирование и повторное монтирование проходят без ошибок.
- **Тип доказательства**: Скриншот + DOM-проверка.

### 2.3. Граничные значения и слоты (BND)

#### TC-BND-001: Числовой `0`, пустой список, Unicode/Emoji, длинный текст в узком контейнере
- **Приоритет**: P1
- **Категория**: `BND`
- **Предусловия**: Прокрутить страницу к секции `Boundaries`.
- **Шаги**: Проверить отображение `Zero Option (0)`, `No options available`, длинного текста с усечением (`ellipsis`) и мультиселекта с `Tiếng Việt 🇻🇳 / Кириллица` в `DemoBox` шириной `240px`.
- **Ожидаемый результат**: Значение `0` распознано и отображается как выбранное; длинные строки и чипы не выходят за пределы `240px`.
- **Тип доказательства**: Скриншот + DOM-проверка.

#### TC-BND-002: Проброска пользовательских слотов Field (`#leading`, `#prefix`, `#suffix`, `#label`)
- **Приоритет**: P1
- **Категория**: `BND`
- **Предусловия**: Прокрутить страницу к секции `Slots (Field & Menu Slots)`.
- **Шаги**: Визуально проверить отображение иконок и текстов слотов `#leading` (`★`), `#prefix` (`[PRE]`), `#suffix` (`[SUF]`) без перекрытия с выбранным значением.
- **Ожидаемый результат**: Все слоты отображаются на своих позициях без наложения текста.
- **Тип доказательства**: Скриншот.

### 2.4. Адаптивность (RSP)

- **Категория**: `RSP`
- **Предусловия**: Установлен viewport `768×1024`.

- **Ожидаемый результат**: Горизонтальный скролл отсутствует (`768 === 768`).
- **Тип доказательства**: Скриншот + метрики viewport.

#### TC-RSP-002: Мобильная верстка (`375×812`)

- **Ожидаемый результат**: Горизонтальный скролл отсутствует (`375 === 375`), поля адаптированы по ширине экрана.
- **Тип доказательства**: Скриншот + метрики viewport.

#### TC-RSP-003: Узкий мобильный экран (`320×568`)
- **Приоритет**: P1
- **Категория**: `RSP`
- **Предусловия**: Установлен viewport `320×568` (`mobile: true`).
- **Шаги**: Проверить `scrollWidth` и целостность сетки.
- **Ожидаемый результат**: Горизонтальный скролл отсутствует (`320 === 320`).
- **Тип доказательства**: Скриншот + метрики viewport.

### 2.5. Доступность (A11Y)

#### TC-A11Y-001: ARIA-атрибуты combobox и фокус клавиатуры
- **Приоритет**: P0
- **Категория**: `A11Y`
- **Предусловия**: Страница загружена на `1440×900`.
- **Шаги**: Подсчитать элементы с `role="combobox"`, `aria-haspopup="listbox"`, `aria-expanded` и программно перевести фокус на первый `input[role="combobox"]`.
- **Ожидаемый результат**: Все элементы управления имеют корректные ARIA-атрибуты (`comboboxCount === 65`, `haspopupCount === 65`, `expandedCount === 65`), активный элемент после фокуса — `INPUT`.
- **Тип доказательства**: DOM-проверка.

### 2.6. Консоль, сеть и производительность (LOG)

#### TC-LOG-001: Чистая консоль браузера, отсутствие исключений и сетевых ошибок
- **Приоритет**: P0
- **Категория**: `LOG`
- **Предусловия**: Сбор логов `Runtime.consoleAPICalled`, `Runtime.exceptionThrown`, `Network.responseReceived` активен на протяжении всего прогона.
- **Шаги**: Проанализировать накопленные диагностические события по завершении всех кейсов.
- **Ожидаемый результат**: `consoleErrors === 0`, `consoleWarnings === 0`, `pageErrors === 0`, `failedRequests === 0`.
- **Тип доказательства**: Логи CDP.
