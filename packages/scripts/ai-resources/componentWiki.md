# AI Prompt: Component Documentation & Development

## 1. Analysis & Resources
- **Component Files:** If not attached, find Vue SFC (`*.vue`), `types.ts`, styles, and any child components in `subcomponents/` in the parent directory (the component root, one level up from the current `wiki/` folder). Analyze them fully to understand the main interface and all internal subcomponents.
- **Master Templates:** You **MUST** read and strictly follow the formatting, rules, and styling classes in `node_modules/@dxtmisha/scripts/ai-resources/componentPrompt.md`.

## 2. Output & Modifications
- **Documentation (`.mdx`, `stories.ts`)** must be saved in the local `wiki/` directory (the folder where you were invoked).
- **Component Source (`.vue`, `types.ts`, `subcomponents/`)** must be saved in the parent directory (one level up).
- **Storybook (`*.stories.ts`):** 
  - Append a 2-4 word description to `meta.title` in the target language: `title: '[project]/[ComponentName] - [short description]'`.
  - **argTypes:** You **MUST** populate and describe **ALL** component properties (props) in `argTypes` without omitting any. For each property, specify its `control` (`'select' | 'boolean' | 'text' | 'number' | 'object' | ...`), `options` (for enums/unions), a clear `description`, and default values (e.g., `table: { defaultValue: { summary: '...' } }`).
  - **args:** Populate `args` **ONLY** when a value is strictly necessary for visual display or rendering of the component. **NEVER** put default values into `args` — omit any argument that matches the component's default value or is not required for visual presentation.
  - **All Possible Story Variations & Tests (`play`):** In addition to the default `Component` story, you **MUST** add all possible stories and automated tests with this component, covering every prop, prop combination, visual and interactive state, slot, event, and edge case. Every test story **MUST** include a `Test` prefix in both its exported identifier (e.g., `export const Test...` or `export const [ComponentName]Test...`) and its `name` property (e.g., `name: 'Test: ...'` in English / `'Тест: ...'` in Russian, or the equivalent in the target language). Every story **MUST** include automated Storybook interaction tests using the `play` function (`import { expect, within, userEvent, waitFor } from 'storybook/test'`) to verify DOM structure, classes, attributes, emitted events, and user interactions.
  - **Subcomponents Stories & Tests (`subcomponents/`):** If child components exist in `../subcomponents/`, you **MUST** also create dedicated stories and `play` tests for each subcomponent to thoroughly test their props, states, slots, and events.
  - **Strict Exclusion of Test Stories from Documentation (`.mdx`):** Test stories (as well as all additional variant and subcomponent stories) **MUST NEVER** appear on the `.mdx` documentation page. Keep them strictly in `*.stories.ts` for Storybook testing only — **NEVER** add, embed, or render them in `.mdx` (do not use `<Canvas>`, `<Story>`, or `<Stories />` in `.mdx`). The `.mdx` file must ONLY reference `Component.Component` inside `<StorybookMain>`, and all documentation examples must use `<Source />`.
- **IMPORTANT OVERRIDE:** Ignore any rules in `componentPrompt.md` about returning output in 5 text parts separated by "#########" or prohibitions on modifying files. You MUST directly modify and save the actual files in the workspace.
