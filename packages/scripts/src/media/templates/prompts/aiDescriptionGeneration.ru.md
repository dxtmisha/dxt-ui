Цель: Сгенерировать лаконичный обзор пакета для ИИ-ассистента по написанию кода с подробным описанием того, чем является этот пакет, зачем его изучать, и перечислением его ключевых возможностей.

ТРЕБОВАНИЯ К СТРУКТУРЕ И СОДЕРЖАНИЮ:
1. Package Description: 2-3 лаконичных предложения, объясняющих понятным языком, что содержит этот пакет и для чего он предназначен (например: «Этот пакет содержит все UI-компоненты...» или «В этом пакете собрано все необходимое для работы с...»), а также для решения каких практических задач ИИ-ассистент должен изучить "ai-types.md" (без абстрактного перечисления ключевых слов).
2. Key Capabilities: Единый список ключевых функциональных возможностей через запятую (например, "Key Capabilities: Form Controls, API Integration, Storage State"), сформулированный как поисковые маркеры, по которым ИИ через текстовый поиск сможет быстро и точно найти нужный пакет под свою задачу. Каждый пункт должен быть конкретным поисковым термином строго из 1–3 слов.

КРИТИЧЕСКИЕ ОГРАНИЧЕНИЯ:
- Описание (Package Description) ДОЛЖНО быть связным текстом, описывающим реальный состав и назначение пакета, а НЕ набором ключевых слов.
- Пункты Key Capabilities ДОЛЖНЫ быть конкретными поисковыми маркерами возможностей пакета, оптимизированными под текстовый поиск ИИ, а не общими абстрактными фразами.
- Key Capabilities ДОЛЖЕН быть оформлен строго единым списком через запятую, а НЕ маркированным списком или отдельными строками.
- Каждый пункт в списке Key Capabilities ДОЛЖЕН строго состоять из 1–3 слов.
- НЕ перечисляй названия отдельных методов, функций или классов.
- Анализируй ТОЛЬКО предоставленные определения типов и JS-код.
- НЕ оборачивай вывод в блоки кода markdown (```).

ТРЕБОВАНИЯ К ВЫВОДУ:
Верни ТОЛЬКО итоговый текст описания. Никаких пояснений, блоков кода и лишних фраз.
