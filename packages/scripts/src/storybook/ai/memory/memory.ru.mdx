# Локальная память пакета (ai-memory.md)

Файл `ai-memory.md` — это механизм долговременной памяти AI-агентов на уровне конкретного пакета монорепозитория. Он позволяет сохранять архитектурный опыт, принятые решения, выявленные ограничения и предпочтения разработчика между сессиями.

В отличие от глобальных файлов правил, память пакета динамически наполняется в процессе совместной работы и обладает наивысшим локальным приоритетом при принятии решений агентом.

## Зачем нужна локальная память в монорепозитории

В крупном проекте с десятками пакетов (`@dxtmisha/d1`, `@dxtmisha/constructor`, `@dxtmisha/styles`, `@dxtmisha/functional` и др.) разные части кодовой базы имеют свою специфику:

- **Изоляция контекста** — правила и ограничения пакета `@dxtmisha/styles` не должны загрязнять контекст пакета `@dxtmisha/functional-basic`.
- **Предотвращение повторных ошибок** — если разработчик однажды указал агенту на специфический нюанс (например, запрет использования таблиц в MDX для `@dxtmisha/scripts`), агент фиксирует это в памяти и никогда больше не повторяет ошибку.
- **Устранение зависимости от истории чата** — при перезапуске контекста или открытии новой сессии агент первым шагом считывает `ai-memory.md` и сразу находится в курсе всех локальных договоренностей.

## Строгие правила ведения ai-memory.md

Для поддержания чистоты и эффективности памяти установлены жесткие правила:

- **Локальное размещение (Строго в корне пакета)**
  Файл `ai-memory.md` размещается исключительно в корне соответствующего пакета (например, `packages/scripts/ai-memory.md`). Использование файла памяти в корне всего монорепозитория для правил конкретного пакета запрещено.

- **Явный триггер разработчика**
  Агент обновляет `ai-memory.md` **только** по прямому указанию разработчика (ключевые слова: «Запомни», «Зафиксируй в памяти», «Remember», «Save to memory») или при согласовании критических архитектурных фиксов.

- **Сохранение целостности и устранение дубликатов (Integrity & Deduplication)**
  При добавлении нового правила разрешено **только удалять явные дубликаты или устранять прямые конфликты**. Само содержимое и формулировки существующих правил не должны изменяться, сокращаться или переписываться. Категорически запрещено удалять ранее установленные правила и ограничения.

- **Только критические архитектурные правила**
  В файл памяти запрещено добавлять рутинные логи изменений, историю чата или временные данные. Фиксируются только архитектурные запреты, договоренности по типизации, форматированию и структуре.

- **Относительные пути**
  В записях памяти используются только относительные пути от корня пакета; абсолютные пути запрещены.

## Пример файла ai-memory.md

```markdown
# AI Workspace Memory (packages/scripts)

This file contains package-specific guidelines for @dxtmisha/scripts.

## Guidelines
- Follow strictly all global development principles from root ai-prompt.md.
- Documentation formatting rules for Storybook:
  - Do NOT use horizontal lines (---).
  - Do NOT use markdown tables (| ... |) — format all structured items as bullet lists (- **Key**: description).
  - Focus on practical developer workflows and actions, not internal engine details.
```

## Сравнение ai-memory.md со встроенной памятью IDE

Современные редакторы кода и AI-плагины (Cursor, Windsurf, Claude Code) предлагают встроенные механизмы сохранения памяти и правил. Однако для профессиональной командной разработки и поддержки библиотек встроенные механизмы имеют три критических недостатка:

- **1. Привязка к вендору (Vendor Lock-in):**
  Память, сохраненная внутри Cursor, не переносится в Windsurf, Claude Code, GitHub Copilot или Antigravity IDE. Файл `ai-memory.md` написан в стандартном Markdown и одинаково понимается любым современным агентом.
- **2. Отсутствие в системе контроля версий (Git):**
  Встроенная память редакторов хранится локально на машине разработчика и не коммитится в репозиторий. В результате при подключении нового разработчика к проекту его AI-ассистент начинает с «чистого листа» и повторяет те же ошибки. Файл `ai-memory.md` хранится в Git и синхронизирует инженерный контекст всей команды.
- **3. Отсутствие модульной изоляции (Package Scopes):**
  Встроенная память редактора чаще всего глобальна на весь репозиторий. В условиях монорепозитория правила для визуального UI-кита будут неизбежно засорять контекст работы над утилитами или бэкендом. Файл `ai-memory.md` строго локализован внутри своего пакета.

## Как использовать память в работе

- **Сохранение договоренности:**
  Разработчик: *«Запомни: во всех storybook-документах этого пакета мы не используем горизонтальные разделители и таблицы»*.
  Агент: добавляет пункт в локальный `ai-memory.md` текущего пакета.

- **Чтение на старте сессии:**
  При получении любой задачи по пакету агент в соответствии с правилом **Chronological Guard** первым делом открывает `ai-memory.md` и учитывает все сохраненные ограничения.
