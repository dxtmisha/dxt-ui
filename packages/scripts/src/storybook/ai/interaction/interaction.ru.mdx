# Взаимодействие с AI-ассистентами

Архитектура AIDD в `dxt-ui` спроектирована для максимальной прозрачности, предсказуемости и экономии контекстных токенов при взаимодействии с AI-ассистентами.

Вместо загрузки гигабайтов кодовой базы монорепозитория в контекстное окно модели, используется многоуровневая стратегия ленивой подгрузки данных и строгая иерархия приоритетов правил.

## Стратегия многоуровневой загрузки контекста

- **Уровень 1: Обзорный контекст (Старт диалога)**
  - Загружается только файл `ai-prompt.md`.
  - Агент получает общие стандарты (AI Code Promise, Vue Style Guide) и краткие визитные карточки всех библиотек (`@dxtmisha/d1`, `@dxtmisha/constructor`, `@dxtmisha/styles`, `@dxtmisha/functional` и др.).
  - *Назначение:* Агент знает обо всех модулях и возможностях системы, не перегружая память деталями.

- **Уровень 2: Углубленный контекст по требованию (On-Demand)**
  - **`ai-types.md`** — детальная спецификация TypeScript (загружается только при необходимости вызвать методы пакета или изучить сигнатуры).
  - **`ai-developer.md`** — внутренние стандарты разработки (загружается только при редактировании исходного кода библиотеки).
  - **`ai-resources/*.md`** — узкопрофильные регламенты (загружаются только при срабатывании триггеров из блока `## Mandatory Rules`).
  - **`ai-screenshot/`** — визуальные снимки и DOM/CSS (загружаются при верстке и стилизации интерфейсов).

- **Уровень 3: Локальная память пакета**
  - **`ai-memory.md`** — динамические правила и уроки, зафиксированные в текущем пакете.

## Иерархия приоритетов (Priority Chain)

При возникновении любых разногласий между файлами документации агент руководствуется строгой иерархией:

- **1. `ai-memory.md` (Высший локальный приоритет)** — локальный опыт и прямые указания разработчика для конкретного пакета переопределяют любые другие правила.
- **2. `ai-instruction.md` (Высший глобальный приоритет)** — проектные директивы в корне монорепозитория, переопределяющие базовые системные регламенты.
- **3. `ai-developer.md`** — утвержденные стандарты и архитектурные чек-листы разработки внутри пакета.
- **4. `ai-resources/*.md`** — специализированные предметные стандарты (например, регламенты цветов, теней, отступов или работы с API).
- **5. `ai-prompt.md`** — базовые системные правила кодирования (AI Code Promise, Vue Style Guide) и описания библиотек.
- **6. `ai-types.md`** — кодовые сигнатуры и декларации типов.

## Практические сценарии взаимодействия

### Сценарий 1: Разработка компонента в @dxtmisha/d1

Разработчик дает задачу: *«Создай компонент D1Badge в пакете @dxtmisha/d1»*.

- **1. Старт:** Агент считывает `ai-prompt.md` и находит секцию пакета `@dxtmisha/d1`.
- **2. Изучение стандартов:** Агент открывает `packages/d1/ai-developer.md` и знакомится со стандартами структуры файлов компонента и интеграции с `@dxtmisha/constructor`.
- **3. Проверка ограничений памяти:** Агент читает `packages/d1/ai-memory.md` и проверяет сохраненные правила.
- **4. Проверка Mandatory Rules:** Агент сверяется с блоком `## Mandatory Rules` из `ai-description.md`, открывает `ai-resources/colors-and-palettes.md` и `ai-resources/rounded.md` для корректного применения токенов скругления и палитр.
- **5. Написание кода:** Компонент создается в строгом соответствии с требованиями всех четырех изученных документов.

### Сценарий 2: Использование пакета как библиотеки в приложении

Разработчик дает задачу: *«Реализуй кэшируемый HTTP-клиент с обработкой ошибок»*.

- **1. Старт:** Агент читает корневой `ai-prompt.md` приложения.
- **2. Обнаружение зависимости:** В сводке библиотек агент находит пакет `@dxtmisha/functional-basic` с описанием *«HTTP client, state storage, i18n localization, ErrorCenter»*.
- **3. Срабатывание триггера:** Описание содержит триггер: *«Study when working with HTTP requests, API caching, or ErrorCenter»*.
- **4. Загрузка типов:** Агент точечно открывает файл `node_modules/@dxtmisha/functional-basic/ai-types.md`.
- **5. Генерация точного кода:** Агент находит класс `ApiFetch`, методы `get()` / `post()` и генератор ошибок `ErrorCenter`, создавая вызовы со 100% точностью и без выдуманных параметров.

### Сценарий 3: Добавление глобальной директивы через ai-instruction.md

Тимлид решает временно ввести строгое ограничение во всех пакетах:

- Создается файл `ai-instruction.md` в корне репозитория с текстом директивы.
- Выполняется команда `npm run prompt`.
- Скрипт внедряет директиву в конец `ai-prompt.md` в секцию `High-Priority Directives`.
- С этого момента любой AI-ассистент при чтении `ai-prompt.md` немедленно исполняет требование во всех пакетах монорепозитория.

## Контрольная матрица взаимодействия

- **При добавлении нового метода или экспорта** ➔ выполняется `npm run types` ➔ обновляются `ai-types.md` и `ai-description.md` ➔ выполняется `npm run prompt` ➔ обновляется глобальный `ai-prompt.md`.
- **При создании нового тематического регламента** ➔ создается файл в `ai-resources/` ➔ выполняется `npm run types` ➔ выполняется `npm run prompt`.
- **При корректировке поведения ИИ в диалоге** ➔ используется триггер «Запомни» ➔ агент дописывает правило в `ai-memory.md` пакета без изменения существующих правил и без необходимости пересборки проекта.
