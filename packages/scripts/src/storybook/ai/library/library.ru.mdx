# Внедрение AIDD в библиотеку и пакеты

Для того чтобы библиотека компонентов, UI-кит или набор утилит могли полноценно взаимодействовать с AI-ассистентами в парадигме AI-Driven Development (AIDD), пакет должен самостоятельно поставлять структурированные машиночитаемые метаданные.

При установке такой библиотеки в проект ассистент автоматически получает доступ к выжимке публичных типов (`ai-types.md`), архитектурному профилю (`ai-description.md`), специализированным регламентам (`ai-resources/`), визуальным снимкам (`ai-screenshot/`) и MCP-ресурсам (`ai-mcp-resources.json`). Это позволяет ИИ использовать библиотеку с нулевыми галлюцинациями и без необходимости вручную передавать исходный код в чат.

## Шаг 1: Установка пакета скриптов

Установите пакет `@dxtmisha/scripts` в `devDependencies` вашей библиотеки:

```bash
npm install @dxtmisha/scripts --save-dev
```

## Шаг 2: Настройка конфигурационного файла design.config.json

Все процессы генерации AI-метаданных управляются через конфигурационный файл `design.config.json` в корне библиотеки (или через механизм наследования `"extends"`).

Конфигурация создается исключительно на стороне библиотеки и определяет параметры подключения к ИИ-провайдеру для форматирования сигнатур и JSDoc:

```json
{
  "aiType": "gemini",
  "aiModel": "gemini-3.7-flash",
  "aiKey": "AIzaSy...",
  "aiConfig": {
    "temperature": 0.2
  }
}
```

Параметры конфигурации:
- **`aiType`** — поддерживаемый провайдер ИИ: `gemini` (включая `gemini-cli`), `openai`, `claude` (включая `claude-cli` и `claude-agent`), а также `zai` (Zhipu AI).
- **`aiModel`** — идентификатор используемой модели (например, `gemini-3.7-flash`, `gpt-4o`, `claude-3-7-sonnet`).
- **`aiKey`** — API-ключ выбранного ИИ-провайдера.
- **`aiConfig`** — дополнительные параметры генерации (например, температура отклика `temperature: 0.2`).

## Шаг 3: Настройка сборочных скриптов в package.json

Добавьте команды генерации типов и визуального контекста в секцию `scripts` файла `package.json` библиотеки:

```json
{
  "scripts": {
    "build": "vite build && vue-tsc --emitDeclarationOnly",
    "types": "npm run build && dxt-types",
    "types:save": "dxt-types-save",
    "screenshot": "dxt-screenshot"
  }
}
```

Критически важное правило: сборка бандла перед генерацией типов. Команда `dxt-types` ставится строго после команды сборки бандла (`npm run build && dxt-types`).
- **Почему это необходимо:** ИИ-генератор анализирует именно скомпилированный финальный пакет. Скомпилированный бандл компактнее сырых исходников: в нем нет промежуточного мусора, приватной вспомогательной логики и неэкспортируемых сущностей. Анализ готового бандла позволяет сформировать максимально чистый и точный контракт публичного API.

Назначение команд:
- **`npm run types`** — полная компиляция типов, очистка AST от приватных полей, обращение к ИИ для оптимизации JSDoc и генерация файлов `ai-types.md`, `ai-description.md` и `ai-mcp-resources.json`.
- **`npm run types:save`** — быстрое обновление метаданных и MCP-ресурсов из существующего кэша типов без повторных сетевых вызовов к API ИИ.
- **`npm run screenshot`** — запуск dev-сервера в headless-браузере, создание скриншотов компонентов (`ai-screenshot/*.webp`), дампа DOM (`screenshot-code.html`) и стилей (`screenshot-styles.css`) для мультимодальных ИИ-моделей.

## Шаг 4: Подготовка метаданных кода и специализированных гайдов

Качественная работа ИИ с библиотекой строится на грамотном оформлении исходного кода и сопутствующих инструкций:

### 1. JSDoc-документирование (Специальные теги и автоматические @keywords)
Для всех публичных методов, функций, интерфейсов и компонентов добавляйте понятные JSDoc-комментарии:
- **`@example`** — практические примеры вызова методов или шаблонов компонентов.
- **`@note`** — архитектурные нюансы, правила жизненного цикла и сайд-эффекты.
- **`@warning`** — ограничения среды выполнения (например, только для браузера или запрет на вызов в шаблоне).
- **`@remarks`** — пояснения сложной инженерной логики.
- **Автоматическая генерация `@keywords`:** Поисковые теги и синонимы (`@keywords`) **генерирует сам ИИ** при выполнении `npm run types` (`dxt-types`). Разработчику не нужно писать их вручную: языковая модель сама анализирует назначение функции и дополняет сигнатуру в `ai-types.md` ассоциативными ключами для быстрого поиска агентами.

```typescript
/**
 * Executes a localized HTTP request with automatic session token binding.
 *
 * Выполняет локализованный HTTP-запрос с автоматической привязкой токена сессии.
 * @example
 * const user = await fetchApi<UserProfile>('/api/user/me')
 *
 * @note Automatically attaches Bearer token from active session storage.
 * @warning Do not invoke directly in component template render cycle.
 * @param url request endpoint URL / URL адрес эндпоинта
 * @param options request options / параметры запроса
 * @returns parsed response data / распарсенные данные ответа
 */
export async function fetchApi<T>(url: string, options?: RequestOptions): Promise<T>;
```

### 2. Архитектурный манифест библиотеки (ai-doc.md)
Создайте файл `ai-doc.md` в корне библиотеки. В нем описываются фундаментальные правила написания кода с использованием данного пакета:
- Архитектурная философия (например: «все компоненты чисто презентационные, логика выносится в composables»).
- Обязательные соглашения и запреты (например: «запрещено использовать сырые HEX-цвета, использовать только токены»).
- При генерации документации содержимое `ai-doc.md` автоматически встраивается в `ai-description.md` и попадает в сводный `ai-prompt.md`.

### 3. Специализированные регламенты (ai-resources/)
Выносите узкопрофильные стандарты в отдельные файлы в папку `ai-resources/` пакета (например, `ai-resources/colors.md`, `ai-resources/skeleton.md`, `ai-resources/storage.md`):
- Описывайте правила по принципу «Антипаттерн vs Рекомендуемый паттерн».
- Скрипт `dxt-types` автоматически проанализирует эти файлы и сформирует блок `## Mandatory Rules` в `ai-description.md`.

## Шаг 5: Настройка .gitignore библиотеки

Сгенерированные артефакты типов и временные директории компиляции должны быть исключены из Git:

```gitignore
ai-types.md
ai-description.md
ai-types-temp
ai-tmp
ai-mcp-resources.json
```

**Важное правило:** Файл `ai-doc.md` и папка `ai-resources/` **не должны** добавляться в `.gitignore` — они пишутся вручную, содержат ключевые архитектурные правила и должны фиксироваться в системе контроля версий Git.

## Шаг 6: Запуск генерации и проверка артефактов

Выполните сборку типов:

```bash
npm run types
```

После выполнения команды в корне пакета появятся:
- **`ai-types.md`** — оптимизированная выжимка всех публичных типов и функций с тегами `@keywords`.
- **`ai-description.md`** — профиль библиотеки с описанием возможностей и блоком `## Mandatory Rules`.
- **`ai-mcp-resources.json`** — манифест ресурсов для протокола Model Context Protocol.

Если библиотека содержит UI-компоненты, запустите генерацию скриншотов:

```bash
npm run screenshot
```

## Шаг 7: Публикация и распространение пакета

Чтобы потребители вашей библиотеки (проекты и другие разработчики) получали готовую AI-инфраструктуру «из коробки», убедитесь, что файлы метаданных включаются в публикуемый пакет.

Проверьте секцию `files` в `package.json` библиотеки:

```json
{
  "files": [
    "dist",
    "ai-types.md",
    "ai-description.md",
    "ai-resources",
    "ai-screenshot",
    "ai-mcp-resources.json",
    "ai-doc.md"
  ]
}
```

При установке опубликованного пакета в любое клиентское приложение команда `dxt-prompt` автоматически обнаружит `ai-description.md` и подключит контракты библиотеки в единый `ai-prompt.md`.
