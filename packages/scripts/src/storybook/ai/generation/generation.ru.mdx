# Генерация документации и типов (dxt-types)

Команда `dxt-types` и лежащий в ее основе класс `DesignTypes` отвечают за автоматическую компиляцию, очистку, сжатие и формирование полного набора AI-артефактов пакета.

Скрипт превращает многотысячные файлы деклараций TypeScript (`.d.ts`) в компактный, оптимизированный по расходу токенов справочник типов `ai-types.md`, формирует архитектурный профиль `ai-description.md` и регистрирует ресурсы для протокола MCP.

## Архитектурный конвейер генерации

Процесс генерации разбит на четкие этапы:

- **1. Сборка деклараций (`DesignTypesBuild`)**
  Скрипт компилирует проект и извлекает `.d.ts` файлы во временную изолированную директорию (например, `ai-types-temp/`).
- **2. Фильтрация и очистка структуры (`DesignTypesMake`)**
  Из деклараций автоматически удаляются все внутренние реализации, приватные (`private`) и защищенные (`protected`) поля и методы. Остается только чистый публичный интерфейс (API).
- **3. Интеллектуальная оптимизация через ИИ (`DesignTypesAi`)**
  ИИ-модель анализирует типы и сопутствующий JavaScript-код, удаляет избыточный шум и форматирует лаконичные JSDoc-описания на английском языке, генерируя файл `ai-types.md`.
- **4. Обработка локальных промптов (`DesignTypesPrompts`)**
  Скрипт сканирует папку `ai-resources/` пакета, собирает заголовки и правила узкопрофильных документов.
- **5. Генерация профиля пакета (`DesignTypesDescription`)**
  Формируется файл `ai-description.md` со структурированным описанием назначения пакета, триггерами изучения и списком `## Mandatory Rules`.
- **6. Регистрация ресурсов MCP (`DesignTypesMcp`)**
  Создается файл `ai-mcp-resources.json`, содержащий URI-декларации всех типов, описаний, скриншотов и промптов пакета для MCP-клиентов.
- **7. Очистка временных файлов**
  Временная директория сборки автоматически удаляется после завершения процесса.

## Управление генерацией через JSDoc-теги

Движок очистки автоматически отсекает тривиальные комментарии, но **гарантированно сохраняет и переносит** в `ai-types.md` специальные архитектурные теги:

- **`@example` (Примеры использования)** — демонстрирует ИИ правильный способ вызова метода, сервиса или компонента.
- **`@note` (Архитектурные примечания)** — фиксирует сайд-эффекты, правила инициализации и жизненного цикла.
- **`@warning` (Предупреждения и ограничения)** — обращает внимание на критические моменты (например, «только для браузера / DOM» или «не вызывать в шаблоне»).
- **`@remarks` (Расширенные комментарии)** — передает развернутое пояснение сложной инженерной логики.
- **`@keywords` (Поисковые теги)** — ключевые слова и синонимы, по которым ИИ-агент быстро находит нужный интерфейс или функцию через текстовый поиск без чтения всего файла.

## Структура создаваемого ai-description.md

Файл `ai-description.md` формирует визитную карточку пакета для главного промпта:

- **Package Description** — краткое определение технической роли пакета (1-2 предложения).
- **Triggers for Studying ai-types.md** — четкий список сценариев, при которых агент обязан прочитать `ai-types.md`.
- **Key Capabilities** — перечень ключевых возможностей (строго по 1-3 слова на пункт).
- **Mandatory Rules** — реестр правил из `ai-resources/` с краткими триггерами.

## Режимы запуска

- **Стандартная генерация с ИИ:**
  ```bash
  npx dxt-types
  ```
  Используется для полной пересборки типов и генерации новых описаний с обращением к API ИИ.

- **Быстрое сохранение без вызова ИИ (`dxt-types-save`):**
  ```bash
  npx dxt-types-save
  ```
  Быстрый режим, объединяющий существующий кэш типов и обновляющий MCP-ресурсы без сетевых запросов к ИИ.
