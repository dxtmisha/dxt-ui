# Publishing Packages to the npm Registry

In the **DXT UI** design system, the package distribution and release process across the entire monorepo is fully automated using the `dxt-build-publish-packages` CLI utility. Developers no longer need to manually check published versions on npm, navigate into separate package directories, or worry about release conflicts.

The tool automatically scans the packages directory, queries current live versions from the public npm registry asynchronously, and safely publishes only modified packages.

## Key Advantages

### 1. Automated Differential npm Registry Auditing
Before publishing, `dxt-build-publish-packages` performs an asynchronous `npm view <package> version` check for every package. Only packages whose local version is newer than the version currently on npm (or packages being published for the first time) are published.

### 2. Conflict-Free Publishing (Zero Conflicts)
The utility prevents `E403` / `E409` errors (Cannot publish over existing version) by completely avoiding publish attempts for unchanged packages.

### 3. Automatic Isolation of Private and Internal Packages
The orchestrator automatically ignores private packages (`"private": true`) as well as packages flagged with `"ui-no-publish": true`.

## Step-by-Step Guide (What to Do)

### Step 1. Configure the package.json File
In your package's `package.json`, ensure the package name, version, and publish scripts are configured properly:

```json
{
  "name": "@dxtmisha/example-package",
  "version": "1.0.1",
  "scripts": {
    "publish-to-npm": "npm publish --access public"
  }
}
```

### Step 2. Bump the Package Version
When code changes are ready for release, increment the version number in the target `package.json` (for example, from `1.0.0` to `1.0.1`).

### Step 3. Run the Publish Command
Execute `dxt-build-publish-packages` in your terminal from the monorepo root:

```bash
npx dxt-build-publish-packages
```

The script audits the npm registry and publishes only the updated packages:

```text
Publish packages(14)...
Publish packages changed: 1
```

If all monorepo packages match the versions on npm, no publish actions are taken:

```text
Publish packages(14)...
Publish packages - no changes
```

## Configuration Flags in package.json

- **`ui-no-publish` (boolean)**: When set to `true`, the package is excluded from publishing regardless of version changes.
- **`private` (boolean)**: Private packages are automatically skipped.
- **`publish-to-npm` (script)**: If defined under `scripts`, the orchestrator executes `npm run publish-to-npm`. Otherwise, it falls back to `npm publish --access public`.

## Advantages Over Manual Publishing

- **Release Safety**: Eliminates human errors and accidental deployment of unintended packages.
- **Single-Command Batch Releases**: Release updates across dozens of packages in a single run.
- **CI/CD Integration**: Seamlessly fits into automated release pipelines upon merging into the main branch.
