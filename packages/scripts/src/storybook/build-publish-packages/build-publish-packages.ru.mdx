# Публикация пакетов в реестр npm

В дизайн-системе **DXT UI** процесс дистрибуции и релиза пакетов монорепозитория в реестр npm полностью автоматизирован с помощью утилиты `dxt-build-publish-packages`. Разработчику больше не нужно вручную проверять опубликованные версии на npm, поочередно заходить в каждый каталог или опасаться конфликтов версий.

Инструмент автоматически сканирует директорию пакетов, асинхронно сверяет текущие версии с публичным реестром npm и безопасно публикует только обновленные модули.

## Преимущества автоматизации

### 1. Автоматический дифференциальный анализ реестра npm
Перед публикацией команда `dxt-build-publish-packages` выполняет сетевой запрос `npm view <package> version` для каждого пакета. Публикуются исключительно те пакеты, локальная версия которых новее версии в реестре npm, либо пакеты, которые публикуются впервые.

### 2. Защита от конфликтов и ошибок (Zero Conflicts)
Утилита предотвращает возникновение ошибок `E403` / `E409` (Cannot publish over existing version), полностью исключая попытки повторной публикации неизмененных пакетов.

### 3. Автоматическая изоляция приватных и служебных пакетов
Оркестратор автоматически игнорирует приватные пакеты (`"private": true`) и пакеты со специальным флагом `"ui-no-publish": true`.

## Пошаговое руководство (Что нужно делать)

### Шаг 1. Настройте конфигурацию package.json
В файле `package.json` пакета убедитесь, что имя пакета, версия и скрипт публикации настроены корректно:

```json
{
  "name": "@dxtmisha/example-package",
  "version": "1.0.1",
  "scripts": {
    "publish-to-npm": "npm publish --access public"
  }
}
```

### Шаг 2. Обновите версию пакета (Bump Version)
Когда изменения в коде готовы к релизу, увеличьте номер версии в `package.json` нужного пакета (например, с `1.0.0` до `1.0.1`).

### Шаг 3. Запустите команду публикации
Выполните команду `dxt-build-publish-packages` в терминале из корня монорепозитория:

```bash
npx dxt-build-publish-packages
```

Скрипт выполнит аудит реестра npm и опубликует обновленные пакеты:

```text
Publish packages(14)...
Publish packages changed: 1
```

Если все пакеты в монорепозитории уже соответствуют версиям в npm, публикация не будет производиться:

```text
Publish packages(14)...
Publish packages - no changes
```

## Конфигурационные флаги package.json

- **`ui-no-publish` (boolean)**: Если установлено в `true`, пакет будет полностью исключен из процесса публикации, даже если его версия отличается от реестра.
- **`private` (boolean)**: Приватные пакеты автоматически пропускаются публикатором.
- **`publish-to-npm` (script)**: Если в секции `scripts` определена команда `publish-to-npm`, оркестратор выполнит `npm run publish-to-npm`. В противном случае используется системная команда по умолчанию `npm publish --access public`.

## Преимущества перед ручной публикацией

- **Безопасность релиза**: Исключен человеческий фактор и ошибки публикации не тех пакетов.
- **Массовая публикация в один клик**: Возможность выпустить обновление для десятков пакетов одной командой.
- **Интеграция с CI/CD**: Идеально подходит для автоматических пайплайнов релизов при слиянии в основную ветку.
