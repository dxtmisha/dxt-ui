# Kiến trúc và Ưu điểm của Hệ thống thiết kế

Package `@dxtmisha/scripts` là hạt nhân hạ tầng và bộ sinh mã (code generator) của hệ thống thiết kế **DXT UI**. Nó triển khai mô hình kiến trúc tiên tiến phân tách triệt để logic hành vi trừu tượng và giao diện trực quan, tự động hóa toàn bộ quy trình khởi tạo, liên kết, định kiểu dữ liệu (typing) và tạo tài liệu cho tất cả component trong thư viện.

Mục tiêu cốt lõi của hệ thống là cung cấp cho các nhà phát triển một quy trình tự động hóa hoàn chỉnh, loại bỏ hoàn toàn mã lặp lại (boilerplate), ngăn ngừa lỗi do con người và đảm bảo tính nhất quán xuyên suốt giữa thiết kế, kiểu dáng SCSS, logic component và TypeScript types.

## Các Ưu điểm Triển khai Vượt trội

### 1. Phân tách Triệt để Logic và Giao diện (Headless + Design System)
Toàn bộ logic hành vi (xử lý bàn phím, bẫy focus, thuật toán vị trí, khả năng truy cập ARIA, đồng bộ trạng thái) được đóng gói hoàn toàn trong `@dxtmisha/constructor`.
- **Dễ dàng tạo mới các UI kit:** Để xây dựng một bộ giao diện mới (ví dụ `d2` hoặc giao diện thương hiệu riêng), bạn không cần viết lại bất kỳ dòng logic phức tạp nào — chỉ cần khai báo file `properties.json` và file styles mới.
- **Độ tin cậy được đảm bảo:** Việc sửa lỗi trong constructor sẽ tự động cập nhật và sửa lỗi cho tất cả các hệ thống thiết kế đang sử dụng constructor đó.

### 2. Không còn mã rập khuôn và Tăng tốc độ phát triển gấp 10 lần (Zero-Boilerplate)
Trong cách tiếp cận truyền thống, việc thêm một prop mới đòi hỏi phải chỉnh sửa thủ công ở 5–7 vị trí khác nhau (types, Vue props, validators, template classes, SCSS selectors, tài liệu).
- Trong DXT UI, lập trình viên chỉ cần thêm **một dòng** vào `properties.json`.
- Lệnh `dxt-ui` chỉ trong vài giây sẽ tự động cập nhật `props.ts`, mapping BEM trong `.vue`, biến SCSS trong `styleToken.scss` và metadata cho IDE.

### 3. Nguồn Chân lý Duy nhất & An toàn Kiểu dữ liệu 100% (100% Type Safety)
File `properties.json` đóng vai trò là nguồn chân lý duy nhất cho toàn bộ không gian làm việc:
- **TypeScript**: Định kiểu nghiêm ngặt cho tất cả các giá trị prop hợp lệ (`size: 'sm' | 'md' | 'lg'`).
- **Kiểm tra Runtime**: Tự động sinh mảng giá trị hợp lệ (`propsValues`) để kiểm tra nhanh bằng các helper `inArray`.
- **Tự động hoàn thành mã trong IDE**: Tự động cập nhật `web-types.json`, cung cấp trải nghiệm IntelliSense mạnh mẽ trong WebStorm và VS Code.
- Loại bỏ hoàn toàn lỗi con người: không còn lỗi chính tả trong tên class BEM, không lệch giữa styles và types, không quên export.

### 4. Tái cấu trúc Toàn cục Tức thì cho Toàn bộ Hệ thống Thiết kế
Khi bạn cần đổi tiền tố class BEM, điều chỉnh quy tắc sinh biến CSS hoặc hỗ trợ chuẩn trình duyệt mới trên hơn 100 component:
- Chỉ cần sửa đổi logic generator trong `@dxtmisha/scripts`.
- Chạy lệnh build sẽ tự động biên dịch lại toàn bộ các component trong monorepo chỉ trong vài giây.

### 5. Quản lý Bảng màu và Theme Khai báo Không làm Phình to CSS
Bộ phân tích cú pháp token hỗ trợ các mô hình styling nâng cao:
- **`flag-theme` & Bảng màu**: Chuyển đổi theme sáng/tối và thay đổi bảng màu động mà không cần nhân bản mã CSS, thông qua các biến CSS cấp bảng màu.
- **Tách rời Màu sắc và Độ mờ (Opacity)**: Hỗ trợ tự nhiên các token với độ mờ độc lập (`backgroundOpacity`, `colorOpacity`).
- **BEM Modifiers thông minh (`flag-subclass`, `flag-replace`)**: Các class modifier chỉ được thêm vào DOM khi các flag tương ứng được kích hoạt.

### 6. Tự động Tiêm Phụ thuộc (Dependency Injection) cho Subcomponent
Component `.vue` được sinh ra tự động liên kết và truyền các thành phần phụ trợ (icon `D1Icon`, loader `D1Progress`, hiệu ứng ripple `D1Ripple`) trực tiếp vào lớp `Design`. Template component giữ được sự gọn gàng và tối giản tuyệt đối:
```html
<script setup lang="ts">
// Liên kết được sinh tự động
const design = new ButtonDesign('d1.button', props, {
  emits,
  classes: classesToken,
  styles: stylesToken,
  components: { icon: D1Icon, progress: D1Progress, ripple: D1Ripple }
})
const render = design.render()
</script>

<template>
  <render/>
</template>
```

### 7. Hệ sinh thái AI-Native và Tự động hóa Tài liệu
- **Sinh `ai-types.md`**: Biên dịch các tài liệu tham khảo kiểu dữ liệu siêu gọn, cho phép các mô hình LLM nhanh chóng hiểu toàn bộ API mà không cần quét hàng ngàn dòng mã nguồn.
- **AI Docs & Storybook MDX**: Tự động tạo mô tả thuộc tính và ví dụ sử dụng tương tác phong phú.
- **Đồng bộ Figma API**: Trực tiếp trích xuất frames, design tokens và styles từ Figma vào mã nguồn dự án.

## Cơ chế Hoạt động Bên dưới

### 1. Khai báo Hợp đồng Giao diện (`properties.json`)
Các thuộc tính hình ảnh của component được khai báo dưới định dạng JSON rõ ràng:
```json
{
  "size": {
    "type": "type-var",
    "value": ["sm", "md", "lg"],
    "default": "md"
  },
  "palette": {
    "type": "flag-theme",
    "value": ["primary", "secondary", "tertiary", "error"]
  },
  "outline": {
    "type": "flag-subclass"
  }
}
```

### 2. Tự động Sinh Mã Nguồn
Công cụ `dxt-ui` biên dịch cấu hình JSON thành các tài nguyên đồng bộ:
1. **`props.ts`**: Kết hợp props từ constructor logic và tokens hình ảnh với các giá trị mặc định.
2. **`styleToken.scss`**: Sinh ra các mixin SCSS và biến CSS cho từng trạng thái token.
3. **`D1[Component].vue`**: Thiết lập bản đồ BEM phản ứng (`classesToken`) và khởi tạo instance `Design`.
4. **`index.ts`**: Đóng gói và export component cùng với tất cả các types liên quan.

## Các Lệnh CLI Chính trong Hệ sinh thái

- **`dxt-ui [ComponentName]`** — Bộ điều phối chính xây dựng UI. Quét `properties.json`, sinh template, bản đồ BEM, typed props và liên kết với lớp Constructor.
- **`dxt-constructor`** — Biên dịch lại các class và interface toàn cục cho logic constructor, giữ cho các types luôn đồng bộ.
- **`dxt-library`** — Quét cây thư mục và tự động cập nhật các file export trong toàn bộ monorepo.
- **`dxt-screenshot`** — Môi trường kiểm thử hồi quy trực quan tự động dựa trên Puppeteer.
- **`dxt-types-save`** — Tạo tài liệu tham khảo `ai-types.md` tối ưu hóa cho AI và các công cụ LLM.
