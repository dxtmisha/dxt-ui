# Design System Architecture and Implementation Advantages

The `@dxtmisha/scripts` package is the automation core and code generator of the **DXT UI** design system. It implements a cutting-edge architectural paradigm that strictly decouples abstract behavioral logic from visual presentation, automating the creation, binding, typing, and documentation of all components across the library.

The primary goal of the system is to provide developers with a fully automated pipeline that eliminates boilerplate, prevents human error, and ensures end-to-end consistency between design, styling, component logic, and TypeScript types.

## Key Implementation Advantages

### 1. Strict Decoupling of Logic and Visual Presentation (Headless + Design System)
Behavioral logic (keyboard handling, focus trapping, positioning math, ARIA accessibility, state synchronization) is fully encapsulated in `@dxtmisha/constructor`.
- **Effortless UI-Kit creation:** Building an alternate theme (e.g., `d2` or a custom corporate brand system) requires zero rewrites of complex component logic — developers simply define new `properties.json` configurations and style files.
- **Guaranteed reliability:** Fixing a bug in the constructor logic instantly resolves the issue across all design systems utilizing that constructor.

### 2. Zero Boilerplate and 10x Development Speed
In traditional component design, adding a single new prop requires manual updates across 5–7 separate locations (types, Vue props, validators, template classes, SCSS selectors, documentation).
- In DXT UI, developers add **one line** to `properties.json`.
- The `dxt-ui` command in seconds automatically updates `props.ts`, BEM class mappings in `.vue`, SCSS variables in `styleToken.scss`, and IDE autocomplete metadata.

### 3. Single Source of Truth & 100% Type Safety
The `properties.json` file serves as the definitive source of truth across the entire workspace:
- **TypeScript**: Strictly types all allowed prop values (`size: 'sm' | 'md' | 'lg'`).
- **Runtime checks**: Automatically generates runtime allowed-value arrays (`propsValues`) for instant validation using `inArray` helpers.
- **IDE Autocomplete**: Automatically updates `web-types.json`, delivering rich IntelliSense in WebStorm and VS Code.
- Human error is physically eliminated: no typos in BEM modifier names, no type-to-CSS mismatches, no forgotten exports.

### 4. Instant Global Refactoring across the Entire Design System
Need to alter a BEM class prefix, adjust CSS variable resolution, or adapt to new browser standards across all 100+ components?
- Modify the generator logic once in `@dxtmisha/scripts`.
- Running the build command re-scaffolds every component across the monorepo in mere seconds.

### 5. Declarative Palettes and Theme Management without CSS Bloat
The token parser handles complex styling patterns seamlessly:
- **`flag-theme` & Palettes**: Dynamic dark/light theme switching and color palette shifts without CSS code duplication using palette-level CSS variables.
- **Decoupled Color & Opacity**: Native support for tokens with independent opacity (`backgroundOpacity`, `colorOpacity`).
- **Smart BEM Modifiers (`flag-subclass`, `flag-replace`)**: Modifier classes are injected into the DOM only when corresponding flags are active.

### 6. Automated Subcomponent Injection via Dependency Injection
The generated `.vue` component automatically wires up and passes subcomponents (such as `D1Icon`, loaders `D1Progress`, press ripple effects `D1Ripple`) directly into the `Design` class. The component template remains clean and minimal:
```html
<script setup lang="ts">
// Automatically generated binding
const design = new ButtonDesign('d1.button', props, {
  emits,
  classes: classesToken,
  styles: stylesToken,
  components: { icon: D1Icon, progress: D1Progress, ripple: D1Ripple }
})
const render = design.render()
</script>

<template>
  <render/>
</template>
```

### 7. AI-Native Ecosystem and Automated Documentation
- **`ai-types.md` Generation**: Compiles tokenized, lightweight type references allowing LLMs to quickly grasp library APIs without scanning thousands of lines of raw source code.
- **AI Docs & Storybook MDX**: Automatically enriches component documentation with prop definitions and interactive usage examples.
- **Figma API Synchronization**: Directly pulls frames, design tokens, and styles from Figma files into the codebase.

## How It Works Under the Hood

### 1. Visual Contract Declaration (`properties.json`)
The visual capabilities of a component are declared in a clean JSON format:
```json
{
  "size": {
    "type": "type-var",
    "value": ["sm", "md", "lg"],
    "default": "md"
  },
  "palette": {
    "type": "flag-theme",
    "value": ["primary", "secondary", "tertiary", "error"]
  },
  "outline": {
    "type": "flag-subclass"
  }
}
```

### 2. Automated File Generation
The `dxt-ui` utility compiles the JSON configuration into synchronized assets:
1. **`props.ts`**: Merges base constructor props and visual tokens with default values.
2. **`styleToken.scss`**: Emits SCSS mixins and CSS variables for each token state.
3. **`D1[Component].vue`**: Configures reactive BEM class mappings (`classesToken`) and initiates the `Design` instance.
4. **`index.ts`**: Packages and exports the component alongside all associated types.

## Main Ecosystem CLI Commands

- **`dxt-ui [--name NAME]`** — Primary UI builder orchestrator. Scans `properties.json`, builds templates, BEM maps, typed props, and binds them to Constructor classes.
- **`dxt-constructor`** — Rebuilds global classes and interfaces for the logic constructor, keeping component types in sync.
- **`dxt-library`** — Scans workspace directory structures and automatically generates entry export files across all monorepo packages.
- **`dxt-screenshot`** — Automated visual regression testing suite powered by Puppeteer.
- **`dxt-types-save`** — Generates AI-optimized `ai-types.md` references for LLM toolchains and coding assistants.
