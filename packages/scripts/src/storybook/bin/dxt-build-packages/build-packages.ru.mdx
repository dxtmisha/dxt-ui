# dxt-build-packages

Команда `dxt-build-packages` обеспечивает автоматическую инкрементальную сборку npm-пакетов в рабочем пространстве монорепозитория. Инструмент использует класс `BuildPackages` и обертку `PackageFile` для сканирования директорий пакетов, сортировки их по приоритету сборки, отслеживания изменений версий через локальный лог-кэш и компиляции только тех пакетов, версии которых обновились.

## Ключевые возможности

- **Автоматическое сканирование монорепозитория**: Сканирует директорию пакетов (`packages/`) и находит все активные модули, содержащие валидный файл `package.json`.
- **Сортировка по приоритету сборки (`ui-priority`)**: Автоматически упорядочивает пакеты по свойству `ui-priority` из `package.json` (по умолчанию `500`), обеспечивая корректный порядок сборки зависимостей от базовых пакетов к высокоуровневым.
- **Инкрементальное кэширование на основе версий**: Предотвращает повторную сборку неизмененных пакетов, сохраняя версии в локальном кэше логов. Сборка выполняется только при обнаружении новой или измененной версии.
- **Пользовательский код сборки (`--code`)**: Возможность переопределить команду сборки (например, `dxt-build-packages --code=types`).
- **Пользовательский лог-файл и `.gitignore` (`--log`)**: Возможность указать имя файла лога (например, `--log=ui-types`), при этом путь к файлу автоматически регистрируется в `.gitignore`.
- **Интеллектуальный выбор скрипта сборки**: При отсутствии явной команды автоматически выбирает первую доступную команду сборки из `package.json` в строгом порядке приоритета: `prepublishOnly`, затем `build-recovery`, затем `build`.
- **Исключение тестовых пакетов**: Автоматически пропускает пакеты, помеченные свойством `"ui-test": true` в `package.json`.

## Как это работает?

Процесс сборки пакетов выполняет следующий пошаговый алгоритм:

1. **Сканирование и загрузка кэша**: Класс `BuildPackages` считывает файл кэша логов (`./logs/ui-build.log.json` или пользовательский файл) и сканирует рабочую директорию пакетов (`packages/`).
2. **Фильтрация пакетов**: Для каждой папки создается экземпляр `PackageFile`. Отфильтровываются папки без `package.json` и тестовые пакеты (`"ui-test": true`).
3. **Сортировка по приоритету**: Оставшиеся пакеты сортируются по возрастанию значения `ui-priority` (при отсутствии свойства используется значение по умолчанию `500`).
4. **Проверка согласованности версий**: Для каждого пакета проверяется соответствие текущей версии в `package.json` значению из кэша логов.
5. **Выполнение команды сборки**: Если версия изменилась (или пакет собирается впервые):
   - Если задан `--code`, выполняется переданная команда или `npm run <code-name>`.
   - Иначе скрипт сборки определяется по порядку приоритета в `package.json` (`prepublishOnly` -> `build-recovery` -> `build`).
6. **Обновление логов**: При успешном выполнении сборки версия пакета фиксируется в оперативной памяти.
7. **Сохранение кэша и обновление .gitignore**: Если хотя бы один пакет был собран (`changed > 0`), обновленный кэш сохраняется на диск, а путь к файлу лога добавляется в `.gitignore`. Если изменений не было, выводится сообщение `Build packages - no changes`.

## Использование

Запустите команду сборки пакетов через CLI:

```bash
# Стандартная инкрементальная сборка пакетов
npx dxt-build-packages

# Сборка типов с отдельным лог-файлом
npx dxt-build-packages --code=types --log=ui-types
```

Либо добавьте вызов в скрипты `package.json` корневого репозитория:

```json
{
  "scripts": {
    "build:packages": "dxt-build-packages",
    "build:types": "dxt-build-packages --code=types --log=ui-types"
  }
}
```

### Доступные флаги CLI

- `-c, --code <CODE>`: Пользовательская команда или имя скрипта для выполнения (например, `types` или `npm run build:prod`).
- `-d, --dir <DIR>`: Путь к директории пакетов (по умолчанию `packages`).
- `-l, --log <LOG>`: Пользовательское имя или путь к файлу лога сборки (по умолчанию `ui-build.log.json` в папке `logs/`).

## Дополнительная информация

### Управление приоритетом сборки (`ui-priority`)

Чтобы базовые библиотеки (например, утилиты или базовые стили) собирались раньше зависимых компонентов, укажите числовой приоритет в `package.json` пакета (меньшее число означает более ранний запуск сборки):

```json
{
  "name": "@dxtmisha/functional-basic",
  "ui-priority": 100
}
```

Пакеты со значением `ui-priority: 100` будут скомпилированы раньше пакетов с `ui-priority: 500` или пакетов без указанного приоритета.

### Исключение тестовых пакетов (`ui-test`)

Чтобы сборщик полностью игнорировал пакет, добавьте в его `package.json`:

```json
{
  "ui-test": true
}
```
