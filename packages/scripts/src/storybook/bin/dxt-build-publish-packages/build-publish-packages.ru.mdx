# dxt-build-publish-packages

Команда `dxt-build-publish-packages` обеспечивает автоматическую инкрементальную публикацию npm-пакетов в рабочем пространстве монорепозитория. Инструмент использует класс `BuildPublishPackages` и обертку `PackageFile` для сканирования директорий пакетов, проверки обновлений версий через локальный лог-кэш и публикации новых релизов в реестр npm.

## Ключевые возможности

- **Автоматическое сканирование монорепозитория**: Обнаруживает активные директории пакетов внутри папки `/packages/`, содержащие корректный файл `package.json`.
- **Инкрементальное кэширование на основе версий**: Избегает избыточных повторных публикаций благодаря ведению локального кэша в файле `./logs/ui-publish.log.json`. Публикация пакета запускается только в том случае, если его версия в `package.json` изменилась по сравнению с сохраненной в кэше.
- **Интеллектуальный выбор скриптов публикации**: Автоматически выполняет скрипт `"publish-to-npm"`, если он определен в `package.json`, с переходом на стандартную команду `npm publish --access public`, если кастомный скрипт отсутствует.
- **Синхронизация базовых версий**: Автоматически регистрирует существующие пакеты при первом запуске, если они отсутствуют в лог-кэше.
- **Исключение из публикации**: Автоматически пропускает пакеты, помеченные как приватные (`"private": true` в `package.json`) или содержащие свойство `"ui-no-publish": true`.
- **Прозрачный вывод процесса**: Логирует подробный вывод stdout и stderr процесса публикации в консоль в реальном времени.

## Как это работает?

Процесс публикации пакетов выполняет следующий пошаговый алгоритм:

1. **Сканирование и загрузка кэша**: Класс `BuildPublishPackages` считывает файл кэша публикаций `./logs/ui-publish.log.json` и сканирует рабочую директорию пакетов (`packages/`).
2. **Фильтрация пакетов**: Для каждой папки создается обертка `PackageFile`. Отфильтровываются папки без `package.json`, а также пакеты с `"private": true` или `"ui-no-publish": true`.
3. **Проверка состояния публикации**:
   - **Первичная регистрация**: Если пакет отсутствует в лог-кэше (`this.log[name] === undefined`), его текущая версия вносится в кэш без вызова команды публикации.
   - **Обновление версии**: Если пакет уже зарегистрирован в логе и его версия в `package.json` отличается от кэшированной (`isUpdate`):
     - Если существует скрипт `"publish-to-npm"`, выполняется команда `npm run publish-to-npm`.
     - В противном случае выполняется команда `npm publish --access public`.
4. **Синхронизация логов**: При успешном завершении публикации новая версия пакета фиксируется в оперативной памяти.
5. **Сохранение кэша**: Если один или несколько пакетов были зарегистрированы или опубликованы (`changed > 0`), обновленный кэш сохраняется на диск в `./logs/ui-publish.log.json`. Если изменений не было, выводится сообщение `Publish packages - no changes`.

## Использование

Запустите команду публикации через CLI:

```bash
npx dxt-build-publish-packages
```

Либо добавьте вызов в скрипты `package.json` корневого репозитория:

```json
{
  "scripts": {
    "publish:packages": "dxt-build-publish-packages"
  }
}
```

## Дополнительная информация

### Файл кэширования логов (`ui-publish.log.json`)

Локальный кэш версий хранится по пути:
```
./logs/ui-publish.log.json
```

Если вы хотите принудительно переопубликовать все пакеты независимо от их текущих версий, вы можете удалить этот файл или очистить его содержимое до `{}`.

### Исключение пакетов из публикации

Если вы хотите, чтобы публикатор игнорировал конкретный пакет, добавьте одно из следующих свойств в его файл `package.json`:

```json
{
  "private": true
}
```
или:
```json
{
  "ui-no-publish": true
}
```

### Кастомная команда публикации

Вы можете настроить специализированный скрипт публикации в секции `scripts` файла `package.json` конкретного пакета:

```json
{
  "scripts": {
    "publish-to-npm": "npm publish --access public --tag next"
  }
}
```
