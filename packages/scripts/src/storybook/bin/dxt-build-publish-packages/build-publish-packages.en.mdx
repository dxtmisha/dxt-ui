# dxt-build-publish-packages

The `dxt-build-publish-packages` command provides automated incremental publishing of npm packages across the monorepo workspace. It utilizes the `BuildPublishPackages` class and `PackageFile` wrapper to scan package directories, verify version updates via a local log cache, and publish new releases to the npm registry.

## Key Features

- **Automated Monorepo Scanning**: Discovers active package directories under `/packages/` that contain a valid `package.json`.
- **Incremental Version-Based Caching**: Avoids redundant publications by maintaining a local version registry in `./logs/ui-publish.log.json`. Publication is triggered only when a package's version in `package.json` differs from the cached value.
- **Intelligent Script Resolution**: Automatically executes the `"publish-to-npm"` script if defined in `package.json`, falling back to standard `npm publish --access public`.
- **Baseline Version Synchronization**: Automatically registers untracked packages into the cache on first run without dispatching unwanted publish calls.
- **Publish Exclusion**: Automatically skips packages marked as private (`"private": true` in `package.json`) or flagged with `"ui-no-publish": true`.
- **Real-Time Stream Logging**: Forwards full stdout and stderr streams of publication commands directly to the console.

## How does it work?

The package publication workflow automates version verification and release dispatching:

1. **Scan and Cache Initialization**: The `BuildPublishPackages` class reads the publication cache `./logs/ui-publish.log.json` and scans the packages directory (`packages/`).
2. **Filter & Validate**: For each directory, it instantiates a `PackageFile` wrapper to verify that `package.json` exists and that it is not excluded (`!packageFile.isNoPublish()`).
3. **Publication Status Check**:
   - **Baseline Registration**: If the package is not yet in the log cache (`this.log[name] === undefined`), its current version is recorded in the cache without running a publish command.
   - **Version Upgrade**: If the package is already logged and its version in `package.json` differs from the cache (`isUpdate`):
     - If `"publish-to-npm"` script exists, it executes `npm run publish-to-npm`.
     - Otherwise, it executes `npm publish --access public`.
4. **Log Synchronization**: Upon successful publication of a package, its version is updated in the in-memory cache.
5. **Persist Logs**: If one or more packages were registered or published (`changed > 0`), the updated cache is saved back to `./logs/ui-publish.log.json`. If no packages required changes, it logs `Publish packages - no changes`.

## Usage

Run the publish command via CLI:

```bash
npx dxt-build-publish-packages
```

Or configure it in the monorepo's root `package.json` scripts:

```json
{
  "scripts": {
    "publish:packages": "dxt-build-publish-packages"
  }
}
```

## Additional Information

### Log Cache File (`ui-publish.log.json`)

The local version cache is stored at:
```
./logs/ui-publish.log.json
```

If you wish to force-republish all packages regardless of version consistency, you can delete this file or reset its contents to empty `{}`.

### Excluding Packages from Publishing

If you want a package to be ignored by the publisher, add one of the following properties to its `package.json`:

```json
{
  "private": true
}
```
or:
```json
{
  "ui-no-publish": true
}
```

### Custom Publish Command

You can define a custom publication script inside the `scripts` section of a package's `package.json`:

```json
{
  "scripts": {
    "publish-to-npm": "npm publish --access public --tag next"
  }
}
```
