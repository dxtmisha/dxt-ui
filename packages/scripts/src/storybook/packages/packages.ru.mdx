# Создание и инициализация пакетов монорепозитория

В дизайн-системе **DXT UI** процесс создания новых пакетов и библиотек в монорепозитории полностью автоматизирован с помощью утилиты `dxt-package`. Разработчику больше не нужно вручную настраивать сборочные конфигурации, прописывать TypeScript-конфиги, формировать `package.json` или подключать новый модуль к Storybook.

Команда `dxt-package` (исполняемый файл `bin/design-package.ts`, класс `PackageInit`) сканирует монорепозиторий на наличие пустых директорий и за секунду разворачивает готовое изолированное рабочее пространство со всеми необходимыми файлами и интеграциями.

## Преимущества автоматизации

### 1. Эталонное окружение с нуля (Zero Boilerplate)
Вместо ручного создания десятков конфигурационных файлов разработчик создает только одну пустую папку в `packages/`. Утилита автоматически генерирует полную инфраструктуру: TypeScript, Vite, ESLint/Prettier-совместимые настройки, скрипты сборки, тестирования и публикации.

### 2. Автоматическая интеграция в Storybook
При создании пакета скрипт автоматически обновляет конфигурацию `.storybook/main.ts` в `packages/storybook`, добавляя пути к MDX-документации и историям нового пакета. Истории и документация становятся доступны сразу без ручной правки настроек.

### 3. Готовая интеграция с ИИ и стандартами типизации
Каждый новый пакет сразу содержит структуру `ai-resources/`, системные файлы `ai-prompt.md` и `ai-memory.md`, а также эталонную точку входа `src/library.ts` со строгой типизацией.

## Пошаговое руководство (Что нужно делать)

### Шаг 1. Создайте пустую папку для пакета
В директории `packages/` создайте новую пустую папку с именем будущего пакета в kebab-case (например, `media-player` или `notifications`):

```bash
mkdir packages/media-player
```

### Шаг 2. Запустите команду генерации пакета
Выполните команду `dxt-package` в терминале:

```bash
npx dxt-package
```

Генератор автоматически обнаружит пустую папку и создаст в ней полный комплект файлов:

```text
Initializing package of type: library with templates: undefined
Package init in: packages/media-player
Update storybook...
```

### Шаг 3. Изучите сгенерированную структуру
Внутри новой папки будет развернута полноценная среда пакета:

```text
packages/media-player/
├── package.json               # Манифест с зависимостями, скриптами сборки и экспортами
├── tsconfig.json              # Базовая конфигурация TypeScript
├── tsconfig.app.json          # Настройки сборщика приложения
├── tsconfig.node.json         # Настройки Node.js окружения
├── vite.config.ts             # Конфигурация сборки библиотеки Vite
├── .gitignore                 # Изоляция локальных файлов и артефактов сборки
├── README.md                  # Документация пакета
├── LICENSE                    # Лицензия проекта (MIT)
├── CHANGELOG.md               # История изменений и версий
├── ai-prompt.md               # Системный контекст пакета для ИИ
├── ai-memory.md               # Локальная память ИИ-ассистента
├── src/
│   ├── library.ts             # Главная точка входа и barrel-экспорт
│   ├── config.ts              # Конфигурация и константы пакета
│   └── types.ts               # Типы и интерфейсы
```

### Шаг 4. Дополнительные опции команды (типы пакетов и шаблоны)
Команда `dxt-package` поддерживает гибкие опции командной строки:

- **По умолчанию (библиотека TypeScript)**:
```bash
npx dxt-package
```

- **Указание типа пакета (например, vue)**:
```bash
npx dxt-package --type vue
```

- **Передача пользовательских шаблонов**:
```bash
npx dxt-package --type vue --templates "template1,template2"
```

- **Указание нестандартной базовой директории**:
```bash
npx dxt-package --dir custom-packages
```

Доступные опции:

- `--type` (`-t`): Тип шаблона пакета. По умолчанию `library`.
- `--templates`: Директория с шаблонами пакетов.
- `--dir` (`-d`): Целевая директория пакетов. По умолчанию `packages`.

Выполните `npx dxt-package --help`, чтобы вывести полный список доступных опций.

## Автоматические интеграции пакета

- **Storybook (`.storybook/main.ts`)**: Скрипт проверяет наличие Storybook и добавляет паттерны `../../${name}/src/**/*.mdx` и `../../${name}/src/**/*.stories.@(js|jsx|mjs|ts|tsx)`.
- **Имя пакета и префикс**: Автоматически генерируется полное имя пакета вида `@dxtmisha/<name>` на основе конфигурации проекта.
- **Стандартные скрипты `package.json`**:
  - `"dev"`: Запуск локального сервера разработки Vite.
  - `"build"`: Компиляция библиотеки (`vite build`).
  - `"test"`: Запуск тестов через Vitest.
  - `"prepublishOnly"`: Автоматическая пересборка перед публикацией.
  - `"publish-to-npm"`: Публикация в публичный реестр npm (`npm publish --access public`).

## Преимущества перед ручным созданием

- **Мгновенный старт**: Создание готовой рабочей среды пакета занимает менее секунды.
- **100% архитектурная точность**: Исключены ошибки конфигурации Vite, TypeScript и забытые экспорты.
- **Сквозная связность монорепозитория**: Автоматическая регистрация в Storybook и единые стандарты версионирования.
