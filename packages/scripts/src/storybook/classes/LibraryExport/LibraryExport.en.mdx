# LibraryExport Class

The `LibraryExport` class is responsible for aggregating and generating unified export files for the library. It scans designated subfolders for TypeScript and Vue files, automatically compiling all exports into a single public interface to simplify library imports. It also supports generating a lightweight sub-library export without components or styles.

## Key Features

- **Unified Export Generation** — Creates a comprehensive public entry point for all components, composables, functions, and classes.
- **Smart Module Detection** — Automatically applies standard wildcard exports (`export *`) for TypeScript utilities and creates named exports for Vue SFC components.
- **Style Integration** — Automatically checks for and integrates global CSS or SCSS stylesheets, with an option to exclude them.
- **Sub-Library Support** — Generates a secondary component-free and style-free entry point (`src/library/_library.ts`) for headless or logic-only usage.
- **Intelligent Filtering** — Excludes unit test files (`.test.`) and modules marked with the `// export:none` directive.

## Initialization

Initialize and execute the library export generator using the `make` method. You can configure whether styles are included and whether a sub-library export is created:

```typescript
import { LibraryExport } from '@dxtmisha/scripts'

// Standard export (with styles, main library only)
const generator = new LibraryExport()
generator.make()

// Export without styles
const noStyleGenerator = new LibraryExport(false)
noStyleGenerator.make()

// Export with both main library and sub-library
const fullGenerator = new LibraryExport(true, true)
fullGenerator.make()
```

### Constructor Parameters

- `style: boolean = true` — Whether to include global stylesheets in the exported library.
- `sub: boolean = false` — Whether to generate an additional sub-library file (`src/library/_library.ts`) without components and styles.

## Methods

### Core Execution

#### `make`
Triggers the main library compilation and entry point generation. It scans all configured subdirectories, collects valid files, filters out test/none-export modules, and writes the unified import/export statements into `UI_DIRS_FILE_EXPORT` (`src/library.ts`). When sub-library generation is enabled (`isSub() === true`), it additionally compiles and writes `UI_DIRS_FILE_EXPORT_SUB` (`src/library/_library.ts`).

**Parameters:**
- No parameters required.

**Returns:** `void` — Writes the target files on the filesystem and logs progress to the console.

```typescript
import { LibraryExport } from '@dxtmisha/scripts'

new LibraryExport(true, true).make()
```

### Helper Methods

- `getPath(directory: string): string[]` — Returns the directory path components based on `UI_DIR_IN` and the specified directory name.
- `isExport(path: string | string[]): boolean` — Evaluates if a file path is suitable for export by verifying it is not a test file and does not match `UI_FLAG_NOT_EXPORT`.
- `isStyle(): boolean` — Checks whether global styles should be included in the export.
- `isSub(): boolean` — Checks whether the sub-library export file should be generated.
- `getDirectory(): LibraryFiles` — Collects recursively all indexable files within the configured export folders and aggregates them.
- `getName(name: string): string` — Converts the first character of the directory name to uppercase to standardize comments in the generated file.
- `getFile(path: string | string[]): string` — Reads the file contents at the given path from the filesystem.
- `initFile(isSub?: boolean): string` — Builds the raw content of the output library file, including imports, style setups, and wildcard/named exports. When `isSub` is `true`, components and styles are excluded and relative paths are adjusted.
- `initStyles(): string` — Generates imports for global stylesheets (`style.scss` or `style.css`) if they are present in the root of the source directory and `isStyle()` is `true`.

## Dependencies and Configurations

The `LibraryExport` class interacts with several global configurations to perform structural generation:

- `UI_DIRS_LIST_EXPORT` — Specifies the active folders that are scanned recursively for exports (`classes`, `components`, `composables`, `functions`, `global`, `types`).
- `UI_DIRS_FILE_EXPORT` — Sets the destination output path of the compiled library file (`src/library.ts`).
- `UI_DIRS_FILE_EXPORT_SUB` — Sets the destination output path of the compiled sub-library file (`src/library/_library.ts`).
- `UI_DIRS_LIBRARY` — Directory path where library-specific outputs are stored (`src/library`).
- `UI_DIR_IN` — Identifies the root source directory containing the modules (`src`).
- `UI_FLAG_NOT_EXPORT` — Holds the regular expression matching the non-export directive (`/\/\/ *export:none/`).
