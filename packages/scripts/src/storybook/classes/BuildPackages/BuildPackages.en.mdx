# BuildPackages Class

The `BuildPackages` class is an orchestrator responsible for scanning, filtering, priority sorting, and incrementally building npm packages across the monorepo workspace. It tracks package version changes using a local log cache file (`./logs/ui-build.log.json` or a custom log file) and compiles only modules whose versions have changed or have not yet been built.

## Key Features

- **Automated Monorepo Scanning**: Scans the packages directory (`packages/`) and discovers all active packages containing a valid `package.json`.
- **Priority-Based Build Ordering (`ui-priority`)**: Sorts packages by `ui-priority` (defaults to `500`, ascending order), ensuring lower-level utility and design packages build prior to dependent high-level components.
- **Incremental Version-Based Caching**: Compares the package version with the log cache to prevent rebuilding unchanged code.
- **Custom Log File & GitIgnore Synchronization**: Supports custom log file naming and automatically registers the generated log path into `.gitignore`.
- **Intelligent Script Resolution**: Supports custom build commands/scripts (`code`) or automatically resolves the first available build command in `package.json` following strict priority order:
  1. `prepublishOnly` (Priority 1)
  2. `build-recovery` (Priority 2)
  3. `build` (Priority 3)
- **Test Package Filtering**: Ignores packages marked with `"ui-test": true`.
- **Automatic Log Persistence**: Writes updated build versions to the log file only when at least one package was successfully compiled (`changed > 0`).

## Constructor

The constructor accepts a custom packages directory path (defaults to the `UI_DIR_PACKAGES` constant = `'packages'`), an optional build command (`code`), an optional log file name or path (`logFile`), and loads the existing build cache log:

```typescript
import { BuildPackages } from '@dxtmisha/scripts'

// Initialize using default packages directory ('packages')
const builder = new BuildPackages()

// Or specify a custom packages path, build command, and custom log file
const customBuilder = new BuildPackages('custom-packages', 'npm run types', 'ui-types')
await customBuilder.make()
```

### Class Properties

- `protected readonly path: string` — Monorepo packages root directory path (defaults to `'packages'`).
- `protected readonly code?: string` — Custom build command or npm script name (e.g., `'types'` or `'npm run types'`).
- `protected readonly logFile?: string` — Custom build log file name or path (e.g., `'ui-types'` or `'logs/ui-types.log.json'`).
- `protected readonly log: Record<string, string>` — In-memory map of cached package versions `{ [packageName]: version }`.

## Methods

- `make(): Promise<void>` — Main orchestration pipeline:
  1. Retrieves the sorted list of valid packages via `getList()`.
  2. Logs total discovered packages count (`Build packages(N)...`).
  3. For each package, verifies whether an update is required (`isUpdate`).
  4. Triggers package compilation if needed (`build`).
  5. On successful build, updates the in-memory version log (`updateLog`) and increments `changed` count.
  6. If `changed > 0`, saves the updated log file to disk (`saveLog`) and logs `Build packages changed: N`.
  7. Registers the log file in `.gitignore` (`initGitIgnore`).
  8. If no packages required compilation, logs `Build packages - no changes`.
- `protected isUpdate(packageFile: PackageFile): boolean` — Checks if a package requires rebuilding via `!packageFile.isVersionConsistency(this.getVersionLog(packageFile.getName()))`.
- `protected getCode(packageFile: PackageFile): string | undefined` — Resolves the build command: uses provided `this.code` (converting script names to `npm run <script>` when appropriate) or falls back to `packageFile.getCodeBuildOrRecovery()`.
- `protected getLogPath(): string[]` — Returns the path segments to the build log file based on `this.logFile` (defaults to `['.', 'logs', 'ui-build.log.json']`).
- `protected getVersionLog(name: string): string` — Retrieves the cached package version from the log (returns `'0.0.0'` if the package has not been logged yet).
- `protected updateLog(packageFile: PackageFile): void` — Updates the in-memory version entry `this.log[packageFile.getName()] = packageFile.getVersion()`.
- `protected build(packageFile: PackageFile): Promise<boolean>` — Executes the build command for a package:
  - Resolves the script via `this.getCode(packageFile)`.
  - Runs the build command inside the package directory using the `run` helper function.
  - Returns `true` on successful completion, or `false` on execution failure / if no build script was found.
- `protected initGitIgnore(): void` — Adds the build log file path to `.gitignore` under the `# Logs` section.
- `protected saveLog(): void` — Persists the current in-memory log map `this.log` to the log file via `PropertiesFile.writeByPath`.
- `private getList(): PackageFile[]` — Scans `this.path`, filters directories (ensures `package.json` exists and `"ui-test": true` is absent), and sorts packages in ascending order based on `ui-priority` (defaults to `500`).
