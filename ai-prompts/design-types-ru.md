# Задача: Автоматическая генерация типов и обработка AI-метаданных (Режим Raw & AI Agent)

Выступайте в роли специалиста по технической инфраструктуре и AI-документации проекта `dxt-ui`.
Ваша цель — сгенерировать чистые, оптимизированные определения типов TypeScript (`ai-types.md`), обзор проекта с правилами триггеров промптов (`ai-description.md`) и ресурсы метаданных для MCP-сервера (`ai-mcp-resources.json`).

**КРИТИЧЕСКОЕ ТРЕБОВАНИЕ**: Все эти правила строго должны быть соблюдены.

---

## Обзор рабочего процесса

1. **Шаг 1: Извлечение сырых типов (Raw Mode)**
   Запустите CLI-скрипт в режиме `raw` (без участия ИИ), чтобы собрать файлы деклараций в `ai-types.md` и подготовить пустые целевые файлы:
   ```bash
   npx dxt-types raw
   ```
   *(Альтернатива: `npm run types raw` или `npx vite-node node_modules/@dxtmisha/scripts/bin/design-types.ts raw`)*

2. **Шаг 2: Оптимизация ИИ-агентом (Очистка и ручная обработка JSDoc)**
   ИИ-агент обрабатывает сгенерированный `ai-types.md`. Вся обработка (удаление лишнего, перевод и оптимизация JSDoc) выполняется в один этап СТРОГО ВРУЧНУЮ, блок за блоком. Если файл слишком большой, его необходимо разделить на части и полностью обработать (при разделении файла на части, берите максимально возможный объем за раз, а если есть возможность обработать файл целиком — лучше выбрать обработку целиком). Оставлять файл без обработки («как есть») СТРОГО ЗАПРЕЩЕНО. Использование скриптов СТРОГО ЗАПРЕЩЕНО.

---

## КРИТИЧЕСКОЕ ТРЕБОВАНИЕ: Строго ручная обработка

- **НИКАКИХ СКРИПТОВ**: Написание или выполнение пользовательских скриптов (например, Node.js, Python, регулярные выражения) **СТРОГО ЗАПРЕЩЕНО** для любых задач (очистка, перевод, генерация JSDoc и т.д.). Вся работа должна выполняться ВРУЧНУЮ, независимо от объема и размера файла. Процесс можно разбить на этапы, если файл слишком велик (при разделении берите максимально возможный объем за раз; по возможности обрабатывайте целиком), но `ai-types.md` ДОЛЖЕН быть полностью обработан — оставлять его без обработки («как есть») КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО. Необходимо использовать только инструменты прямого редактирования файлов.
- **ПОЛНАЯ ОБРАБОТКА БЕЗ ПРОПУСКОВ**: Файл ОБЯЗАТЕЛЬНО должен быть обработан ЦЕЛИКОМ. Категорически запрещено что-либо упускать, пропускать или удалять (если это не предусмотрено правилами очистки).
- **ГЛУБОКОЕ РУЧНОЕ ИЗУЧЕНИЕ**: ИИ-агент ОБЯЗАН вручную читать, просматривать и анализировать файлы реализации JS в `dist/` или `src/`, чтобы полностью понять каждую функцию, метод, класс, параметр, возвращаемое значение и побочный эффект.

## КРИТИЧЕСКОЕ ТРЕБОВАНИЕ: Строго английский язык (English-Only Output)

- **СТРОГО ТОЛЬКО АНГЛИЙСКИЙ ЯЗЫК**: Весь сгенерированный текст и контент в `ai-types.md`, `ai-description.md` и `ai-mcp-resources.json` ДОЛЖЕН быть написан **ИСКЛЮЧИТЕЛЬНО НА АНГЛИЙСКОМ ЯЗЫКЕ**.
- **ЗАПРЕТ НА ДРУГИЕ ЯЗЫКИ**: Все существующие комментарии на других языках (русском и т.д.) должны быть переведены на понятный английский язык. Любой неанглийский текст (русский, вьетнамский и т.д.) в JSDoc, комментариях, описаниях, обзорах или метаданных **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕН**.

## КРИТИЧЕСКОЕ ТРЕБОВАНИЕ: Контекст ИИ-потребителя (Нет доступа к исходному коду)

- **ИСКЛЮЧИТЕЛЬНАЯ ОПОРА НА МЕТАДАННЫЕ**: ИИ-агент, который в будущем будет работать с этим пакетом, НЕ УВИДИТ оригинальный исходный код (`dist/` или `src/`) или какие-либо другие файлы реализации. Он будет в своей работе ориентироваться ИСКЛЮЧИТЕЛЬНО на эти сгенерированные файлы метаданных (`ai-types.md`, `ai-description.md` и `ai-mcp-resources.json`).
- **САМОДОСТАТОЧНОСТЬ И ТОЧНОСТЬ**: Каждое определение типа, описание JSDoc, обзор модуля и ресурс MCP ДОЛЖНЫ быть полностью самодостаточными, точными и однозначными, предоставляя весь необходимый контекст стороннему ИИ без необходимости обращения к исходному коду.

## Пошаговая инструкция для ИИ-агента

### Шаг 1: Запуск скрипта в режиме Raw
Запустите `npx dxt-types raw` в директории пакета. Это создаст:
- `ai-types.md`: содержит объединенные `.d.ts` декларации с заголовком `All these methods are in the <package-name> (v<version>) library.`
- `ai-description.md`: создается как пустой файл.
- `ai-mcp-resources.json`: создается как пустой массив (`[]`).

---

### Шаг 2: Оптимизация определений типов (`ai-types.md`)
Прочитайте `ai-types.md` и изучите код реализации JS в `dist/` или `src/` вручную, чтобы очистить и оптимизировать контракты типов для использования ИИ.

#### Правила очистки и оптимизации (Выполняются строго вручную):
- **Сохранение заголовка**: Сохраните первую строку без изменений: `All these methods are in the <package-name> (v<version>) library.`
- **Сохранение всех экспортируемых сущностей**: СТРОГО ЗАПРЕЩЕНО удалять, пропускать или исключать любые экспортируемые функции, методы, классы, интерфейсы или типы. Каждая публичная сущность API, экспортируемая пакетом, ОБЯЗАТЕЛЬНО должна быть сохранена в `ai-types.md`.
- **Импорты и реэкспорты**: Удалите все внутренние `import` и локальные реэкспорты (например, `export * from "./..."`). Оставьте экспорты из внешних пакетов.
- **Ограничение доступа**: Удалите непубличный контент (private/protected члены классов, неэкспортируемые функции). Сохраните все публичные API-поверхности.
- **Типы и Enum**: Сохраните все объявления `type`. Удалите слишком громоздкие Enum или структуры, увеличивающие объем без критической пользы.
- **Осторожность с абстрактными классами**: Проявляйте крайнюю осторожность при рассмотрении вопроса об удалении абстрактных классов: если есть хотя бы 5% вероятности, что абстрактный класс поможет стороннему ИИ понять API или написать код, его ОБЯЗАТЕЛЬНО нужно сохранить.
- **Исключения деклараций**: Исключайте `.vue.d.ts`, `wiki.d.ts`, `wikiData.d.ts` и внутренние файлы конструктора (за исключением `basicTypes.d.ts`, `types.d.ts` и `props.d.ts`).
- **Форматирование и очистка**: ОБЯЗАТЕЛЬНО удаляйте все пустые строки между объявлениями (форматируйте текст плотно). Удаляйте все обычные однострочные и многострочные комментарии (`//` или `/* ... */`), а также все комментарии со ссылками и путями к файлам (например, `// file:...`, `// packages/...`).

#### Правила для JSDoc и комментариев:
- **Изучение JS-реализации**: Проанализируйте код JS вручную, чтобы точно понять полное поведение, параметры и назначения функций/методов.
- **Очевидные сущности (удаление JSDoc)**: Обязательно удаляйте JSDoc у простых и самодокументируемых сущностей, чьё назначение, параметры и возвращаемое значение однозначно понятны из названия (например: базовые проверки типов `isString`, `isArray`, `isObject`, простейшие утилиты `capitalize`, `copyObject`, `random`, `sleep`, `toString`, стандартные геттеры/сеттеры без скрытой логики).
- **Неочевидные и сложные сущности (сохранение/создание JSDoc)**: Сохраняйте или генерируйте JSDoc для всех сущностей с нетривиальной бизнес-логикой, множеством параметров, настройками, опциями или побочными эффектами (например: `replaceTemplate`, `sortList`, `SearchList`, методы `Api`, `GeoIntl`, сложные интерфейсы и типы). Соблюдайте сбалансированный подход: не удаляйте JSDoc у сложных и специализированных функций, но и не оставляйте избыточный JSDoc у очевидных базовых утилит.
- **Компактное форматирование и оптимизация текста**: Форматируйте комментарии JSDoc в компактном однострочном виде (`/** ... */`) всегда, когда это возможно. Оптимизируйте и сокращайте текстовое содержимое JSDoc. Не берите оригинальный текст как есть и не переводите его дословно — переписывайте его так, чтобы он был максимально кратким и емким без потери критического контекста.
- **Неочевидные сущности с JSDoc**: Переведите комментарии на понятный английский язык, оптимизируя и сокращая текст. Сохраните ТОЛЬКО теги `@example`, `@remarks`, `@note` и `@warning` (остальные теги удалите). **КРИТИЧЕСКИ ВАЖНО**: Теги `@example`, `@remarks`, `@note` и `@warning` СТРОГО ЗАПРЕЩЕНО удалять, вырезать или изменять структурно — разрешается только переводить и оптимизировать их текстовое содержимое на английский язык.
- **Неочевидные сущности без JSDoc**: Сгенерируйте точный и краткий английский JSDoc, который сжато отражает назначение, логику работы и параметры функции на основе её JS-реализации.
- **Сложные сущности**: Сгенерируйте краткий английский JSDoc, раскрывающий внутреннюю логику работы, параметры, возвращаемые значения и побочные эффекты JS-реализации, сохраняя его максимально компактным.
- **Расположение**: Размещайте все JSDoc комментарии СТРОГО непосредственно перед соответствующим объявлением.

Сохраните полученный очищенный текст обратно в `ai-types.md`.

### Шаг 3: Генерация обзора проекта и правил (`ai-description.md`)
Проанализируйте `ai-types.md` и код JS-реализации вручную для создания плотного, лаконичного обзора проекта в `ai-description.md`.

#### Структура документа (Единый связный блок текста):
1. **Core Purpose**: 1-2 предложения, суммирующие главную техническую функцию и ответственность библиотеки.
2. **Key Capabilities & Groupings**: Сгруппируйте классы, композиблы или компоненты по функциональным модулям (например, API/Network, Storage, Localization, Form Components, Layout Controls, Utilities) и кратко описать их возможности. НЕ перечисляйте индивидуальные имена методов — группируйте по функции.
3. **Triggers for Studying `ai-types.md`**: При каких конкретных задачах кодирования, ключевых словах или архитектурных потребностях ИИ-агенту обязательно нужно изучить `ai-types.md`?
4. **Integration Context**: 1 предложение, объясняющее, как библиотека связывается с другими пакетами стека.

#### Раздел обязательных правил (Mandatory Rules):
Проверьте директорию `ai-resources/` на наличие файлов промптов. Если файлы промптов существуют, добавьте раздел в следующем формате:

```markdown
## Mandatory Rules
You MUST evaluate whether your task relates to any of the following topics (even if not working directly with this package). If related material is present, you are strictly obligated to read and study the corresponding file before proceeding:
- 'node_modules/<package-name>/<file-path>': <краткое 1-2 предложения описание триггера и темы (максимум 30-35 words на английском)>
```

Сохраните полученный текст в `ai-description.md`.

---

### Шаг 4: Генерация метаданных MCP-ресурсов (`ai-mcp-resources.json`)
Сформируйте массив объектов метаданных ресурсов MCP для `ai-types.md`, `ai-description.md` и любых файлов промптов в `ai-resources/` вручную.

#### Схема элемента ресурса:
```json
{
  "uri": "<package-name>/<file-path>",
  "name": "<Краткий заголовок на английском (2-4 слова)> (<package-name>)",
  "mimeType": "text/markdown",
  "description": "<Плотное описание на английском (1-2 предложения)>"
}
```

#### Пример результата (`ai-mcp-resources.json`):
```json
[
  {
    "uri": "@dxtmisha/functional-basic/ai-types.md",
    "name": "Type Definitions (@dxtmisha/functional-basic)",
    "mimeType": "text/markdown",
    "description": "Compressed and AI-optimized TypeScript declaration contracts for core utilities."
  },
  {
    "uri": "@dxtmisha/functional-basic/ai-description.md",
    "name": "Package Overview & Rules (@dxtmisha/functional-basic)",
    "mimeType": "text/markdown",
    "description": "High-density project overview, key capabilities, and prompt trigger guidelines."
  }
]
```

Сохраните итоговый JSON-массив в `ai-mcp-resources.json`.
